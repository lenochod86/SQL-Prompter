# SQL Prompter: architecture

An extension with custom IntelliSense for SQL Server Management Studio 22.

**Status:** the prototype answered all three questions in SSMS 22.11 (see [Prototype](#prototype)). The MVP runs in SSMS 22.11 (see [MVP](#mvp)). Next steps are in [roadmap.md](roadmap.md).

## Summary

C# and a classic VSIX extension running in the SSMS process. All logic lives in libraries that do not depend on SSMS; the SSMS layer is as thin as possible.

## Main risk

Microsoft states that third-party extensions are not supported in SSMS. SSMS does not block them, but closes reports about them without investigation ([SSMS FAQ][faq]). An SSMS update may break the extension at any time.

## Technology

| Layer | Choice | Reason |
|---|---|---|
| Language | C# | Native language of the editor API |
| SSMS add-in | .NET Framework 4.8, AnyCPU | SSMS is 64-bit and also exists for Arm64 ([FAQ][faq]) |
| Core | .NET Standard 2.0 | Builds and tests also outside Windows |
| Editor integration | MEF and `IAsyncCompletionSource` ([walkthrough][completion]) | Modern API with background computation |
| Metadata | Queries on `sys.*` through `System.Data.Common`, connection from the `Microsoft.Data.SqlClient` in the SSMS process | Fast, read-only, no SMO dependency and no second SqlClient copy |

SSMS 22 is built on Visual Studio 2026 ([FAQ][faq]). According to [another extension author's notes][sqlfluff], `Microsoft.VisualStudio.SDK` 17.14 is used because there is no 18.x package. The prototype confirmed this in SSMS 22.11.

VisualStudio.Extensibility is not used: no document confirms support in SSMS, and according to [the same source][sqlfluff] replacements for parts of the editor API are missing.

## Structure

```text
┌──────────────────── SSMS 22 process ────────────────────┐
│  SqlPrompter.Ssms (VSIX, thin layer)                     │
│  completion · commit · settings                          │
│  current connection                                      │
│        │ own interfaces, no SSMS types                   │
│  ┌─────▼──────────────┐   ┌──────────────────────────┐   │
│  │ SqlPrompter.Core   │◄──│ SqlPrompter.Metadata     │   │
│  │ lexer              │   │ per-database cache       │   │
│  │ context analysis   │   │ background loading       │   │
│  │ suggestion ranking │   └────────────┬─────────────┘   │
│  └────────────────────┘                │                 │
└────────────────────────────────────────┼─────────────────┘
                                         ▼
                                    SQL Server (sys.*)
```

| Project | Target | May depend on |
|---|---|---|
| `SqlPrompter.Core` | netstandard2.0 | Nothing from VS, SSMS or a database |
| `SqlPrompter.Metadata` | netstandard2.0 | Core and `System.Data.Common`; the host supplies the concrete `DbConnection` |
| `SqlPrompter.Ssms` | net48, VSIX | VS SDK, SSMS API, both projects above |
| Tests | Current .NET | Core and Metadata, cases like `SELECT u.| FROM dbo.Users u` with the caret marked |

## Completion flow

1. On the UI thread (`InitializeCompletion`) the batch between `GO` lines is extracted, tokenized and the context determined, e.g. "column of alias `u`".
2. In the same step, missing metadata is identified and loaded in the background.
3. In the background (`GetCompletionContextAsync`) suggestions are built and ranked from the context and the current snapshot.

This flow never waits for the database. Metadata starts loading when a query window is activated, and the columns of user objects are loaded together with the objects, so they are usually ready before the user needs them. Whatever is missing (columns of system views, the very first load) is added on the next completion. Objects defined in the script (CTEs, temporary tables, table variables, variables, parameters) come from the script model, see below.

## Decisions

- **Two parsers.** While typing, SQL is almost always incomplete, so completion uses its own tolerant lexer and a light clause analysis. Microsoft ScriptDOM is used for full analysis of valid statements (formatting, refactoring, diagnostics). ScriptDOM is [open source under the MIT license](https://github.com/microsoft/sqlscriptdom) and supports netstandard2.0 (verified 2026-11-02).
- **Not based on `Microsoft.SqlServer.Management.SqlParser`.** It is [not open source][sqlparser] and its license terms are not verified.
- **Metadata as immutable snapshots.** Every database has its own snapshot. Columns of user objects are loaded with the objects, columns of system views on demand. Refresh by `sys.objects.modify_date`, after DDL in the window and by a manual command.
- **Security.** Passwords are never stored. Metadata goes to disk only optionally, because even object names may be sensitive. No telemetry.
- **Target performance (draft).** Under 50 ms for a list from the cache and no waiting for the network on the UI thread.
- **Only our list.** Our participation suppresses the built-in list (prototype, question 2). The user wants to see only SQL Prompter's suggestions (decided 2026-11-02), so the extension participates everywhere except in strings, comments and numbers. The built-in IntelliSense stays enabled for error underlining and quick info.
  - Where a new or unknown name is typed (alias after `AS`, a variable being declared, `#table` outside a table position, unknown qualifier, three-part name), the list is empty.
  - After `@`, the variables and parameters defined in the script are offered (`ContextKind.Variable`).
  - After `CAST(x AS` and `DECLARE @x`, data types are offered.
  - At positions the extension does not understand (`EXEC`, `VALUES`, `SET @x =` …), keywords, functions and types are offered without a firm selection.
  - With a CTE, derived table, temporary table or table variable, the columns of known sources, aliases and functions are offered.
  - Suggestions carry the "SQL Prompter" filter, which makes the list recognizable.
  - Not verified yet: whether an empty list really suppresses the built-in one.
- **Script model** (`ScriptModel` in Core, implemented in #15, verified in SSMS 22.11 on 2026-11-05). Definitions in the batch before the caret, built from text only and in the background (`GetCompletionContextAsync`), so the UI thread is not slowed down:
  - CTEs of the statement at the caret, `#tables` from `CREATE TABLE` and `SELECT … INTO`, `@tables` from `DECLARE @t TABLE`, variables from `DECLARE`, and the parameters of `CREATE/ALTER PROCEDURE/FUNCTION`;
  - columns of a CTE, `SELECT … INTO` table or derived table come from the first `SELECT` of its query (alias, `AS`, `alias = expr`, last part of `a.b`, `x.*` and `*`); `SELECT *` is expanded from the metadata snapshot and the objects whose columns are not loaded yet are requested in the background (`ScriptColumns.MissingColumns`);
  - items without a name (`SELECT 1`) are skipped, and only the first block of a `UNION` names the columns;
  - the model is never trusted for what it cannot see: a source it cannot resolve stays unknown, as before.
- **SqlClient from the SSMS process.** Our own connection creates `Microsoft.Data.SqlClient.SqlConnection` from the copy SSMS has loaded (verified by the prototype, version 6.0.0.0). The VSIX ships no SqlClient and Metadata works with `DbConnection` only. The SqlClient 6 package does not support netstandard2.0 anyway.
- **System objects.** Metadata is read from `sys.all_objects` and `sys.all_columns`, so `sys.objects` or `INFORMATION_SCHEMA.TABLES` work as in the built-in IntelliSense. System objects are not offered without a schema.
- **Commit keys.** As in the user's SQL Prompt settings: Tab, Enter and Space insert the suggestion; a dot, comma, parenthesis, semicolon, `]` or operator does not (`CommitKeys` in Core, configurable in Tools → Options → SQL Prompter → Behavior since 0.3.0, #9). Every character that ends a word must still end the session: when only Tab and Enter were commit characters, the list stayed open after a space or a dot (verified in SSMS 22.11). The commit manager therefore reports non-inserting characters as a handled commit without inserting anything, so the list closes, the character is typed and a dot opens the next list (verified in SSMS 22.11). Where the user probably types a name of their own (after a table source or an operand), the selection is soft (`SoftSelection`) and typed characters do not commit. Keywords are inserted in lower case when the user started typing in lower case.
- **Metadata refresh in the MVP.** At most once every 30 s, completion checks a fingerprint of `sys.objects` (count and latest `modify_date`) and reloads the snapshot after a change. The manual command SQL Prompter → Refresh Metadata drops all snapshots instead.
- **Refresh after DDL in the window (#8).** The package subscribes to `BeforeExecute` of the DTE command `Query.Execute` and takes the selection, or the whole document, of the active window. `SchemaChangeDetector` (Core, lexer-based, ignores comments and strings) recognizes `CREATE`/`ALTER`/`DROP` of tables, views, procedures, functions, triggers, schemas, synonyms, types and sequences, `sp_rename` and `SELECT … INTO`. If it finds one, the fingerprint is checked 1, 3, 10 and 30 s later regardless of the 30 s interval, because execution is asynchronous and the event fires before it ends. Verified against SQL Server 2025: the fingerprint changes after `CREATE TABLE`, `ALTER TABLE … ADD` and a column `sp_rename`. Verified in SSMS 22.11: the watcher finds `Query.Execute` and the log shows the snapshot refreshed after DDL ran in the window.
- **Verified in SSMS 22.11 with VSIX 0.6.1 (2026-11-04), driven by Claude through UI Automation.**
  - Every item of the list shows "SQL Prompter" in its suffix (#20).
  - `USE db` on an earlier line makes completion use that database although the window is connected to `master`; the log shows the metadata of that database loading (#25). The first completion after a database is first used is empty, the next one has its objects (loading is in the background).
  - `Db.`, `Db..` and `Db.dbo.` offer the objects of the other database, a synonym is offered like a table and its columns come from the target (#25).
  - Choosing a table after `FROM` inserts `dbo.OrderItems AS oi`; columns are inserted as `u.Email` (#23).
  - `SELECT em` without `FROM` offers `Email (Users)`; choosing it gives `SELECT u.Email FROM dbo.Users AS u`, also with `, Name WHERE 1 = 1` after the caret (the `FROM` goes before `WHERE`) (#24). The commit manager must compute the caret position from `span.Start.Position`: `span.Start + n` throws on the replaced snapshot and the default commit then inserts the text a second time.
  - Not verified yet: the options pages, Export and Import Settings, custom aliases, ignored prefixes and the keyword case option.
- **Driving SSMS from a script.** `SSMS.exe -S localhost,1433 -U claude -d master -C -N Optional` shows a confirmation dialog and a login dialog without a password (`-P` is not accepted). `System.Windows.Automation` finds them: invoke "Yes", then set the Password edit through `ValuePattern` and invoke "Connect". The editor is the `Edit` named "Text Editor": `SetFocus`, paste text through the clipboard (no completion triggers) and `SendKeys` for typing. The completion list is a `ListBox` of `IntellisenseMenuItem` elements whose `Text` children hold the name and the suffix; the editor text is readable through `TextPattern`. Killing SSMS with an unsaved window shows a recovery dialog on the next start ("Do Not Recover"); close it with Alt+F4 and "Don't Save" instead.
- **Linked servers (#26, verified in SSMS 22.11 with VSIX 0.8.1; test linked server `SqlPrompterLS` to the Docker instance itself, created with a provider string `Encrypt=Optional;TrustServerCertificate=Yes;UID=…;PWD=…` because the test login cannot create login mappings).** The first load only adds `SELECT name FROM sys.servers WHERE is_linked = 1`, so the initial load does not depend on what is behind the servers. `Srv.` offers the databases (`EXEC sp_catalogs @server_name`), `Srv.Db.` its schemas and objects (`EXEC sp_tables_ex @table_server, @table_catalog`: several hundred rows including system objects, flagged as such, takes a few seconds), `Srv.Db.schema.` and `Srv.Db..` the objects of a schema, and a four-part source such as `Srv.Db.dbo.T t` gets its columns from `EXEC sp_columns_ex` when `t.` is typed. `LinkedServerCache` (Metadata) never waits: it returns what is cached, starts the load in the background (15 s command timeout, 30 s overall) and remembers a failure for 60 s; the first completion after choosing a server or database is therefore empty and the next one has the names. A schema or database of the current database wins over a linked server of the same name. A server that cannot be reached (`BadLS` without a login mapping) only logs "Linked server: loading … failed" and the normal list keeps working. Columns of remote tables carry the type from `TYPE_NAME` with the size, and `NULLABLE`.
- **Keys and JOIN suggestions (#28, verified in SSMS 22.11 with VSIX 0.9.1).** The first metadata load now also reads `sys.foreign_keys` with their column pairs (`sys.foreign_key_columns`, in column order, so multi-column keys keep their order) and the primary keys (`sys.indexes.is_primary_key`); the DDL refresh brings them with the rest because constraints change the `sys.objects` fingerprint. After `JOIN` the tables that have a key to a table of the query, or that a table of the query points to, come first (group −1, sort key "-01") as one item with the whole clause, e.g. `Doprava ON d.IdObjednavka = p.IdObjednavka AND d.IdPolozka = p.IdPolozka`, inserted as `Crm.Doprava AS d ON …`; the name of the key is the suffix and two keys between the same tables give two items. The new table stands left of the `=` for now (the option for the order is #29). The word being typed is parsed as a table source of its own, so it is not counted as a used alias. Columns carry a key kind and the custom list shows a key icon after the type (primary key wins over foreign key). Icons of the custom list are themed with `ImageThemingUtilities.SetImageBackgroundColor` and the theme background (without it they are drawn dark); the list width is estimated from the longest row (420 to 1000 DIPs).
- **Conditions after ON (#29, verified in SSMS 22.11 with VSIX 0.10.0).** At the start of a condition after `ON` (or `AND` / `OR` following it) the analyzer sets `JoinTarget`, the table introduced by the JOIN whose ON is being edited (found through the token index of the source that follows the nearest `JOIN` before the `ON`; the sources parse the whole block, so `JOIN a ON | JOIN b` still finds `a`). `JoinSuggestions.Conditions` links it to every table before it in the query: the whole foreign key (columns joined by `AND`), with the option every single column pair of a multi-column key, then conditions for column names both tables have (those that are a key column in one of the tables before the others), skipping what a key already covers. They are items of the new kind `JoinCondition` (own icon) and sort before everything else: negative groups −4 to −1, which needed the sort key to be `(Group + 100)` as three digits, because the old `Group.ToString("D2")` put "-01" before "-04". Options page *Joins*: new table on the left (off by default: the user's SQL Prompt has "Swap order of columns in join clauses" on, which puts the new table on the right, `u.IdUser = o.IdUser`, while SQL Prompt's own default is `table2.id = table1.id`; confirmed from the user's screenshot of that option), single columns of multi-column keys, columns with the same name, same name needs the same type. The SQL Prompt import takes `IncludePartialFKJoinConditions`, `AlwaysIncludeNameMatchedJoinConditions` and `FlipColumnsOnJoinCondition`; `FlipColumnsOnJoinCondition` (swap) is imported as "new table on the left" = not swap. SQL Prompt's "always include type-matched conditions" (columns of the same type with different names) is not imported or implemented.

- **Ranking by usage (#47, verified in SSMS 22.11 with VSIX 0.24.0, 2026-11-05).** `UsageStatistics` (Core) counts how often an item was chosen: a key is the database plus `Suggestion.UsageKey` (kind, text, suffix, e.g. `Table|Orders|dbo`); at most 5000 keys (the least used are forgotten down to 90 %), JSON as a list of `{key, count}`, a broken file gives empty statistics. Within a group the editor's sort text is `group` + `UsageStatistics.SortPrefix(count)` + text (`Suggestion.RankedSortText`): more used first, counts above 998 equal, never-chosen items keep the alphabetical order, and the group still wins (a column stays above a keyword however often the keyword was chosen). `UsageService` (SSMS) loads `%APPDATA%\SqlPrompter\usage.json` in the background at start (what is chosen before that is merged in), `SqlCommitManager` records the key of every item inserted by a commit key (Enter, Tab, Space …), and the file is written 5 s after the last change through a temporary file. *Rank by usage* (`behavior.rankByUsage`, on by default) switches it off; *SQL Prompter → Reset Usage Statistics* (menu version 10) asks and clears memory and file. Verified: choosing `Orders` twice and `fnOrdersOf` once made the list after `FROM` start with `Orders`, `fnOrdersOf`, then `Customers` (alphabetically `Customers` would be first), and the file held both counts. Not verified: the reset command through the menu, a very long usage file, the list when the setting is switched off at run time (the sort text is chosen per item when the list is built, so it applies from the next list on).

- **Expanding * and parameter info (#45, verified in SSMS 22.11 with VSIX 0.22.0, 2026-11-05, test objects in `tests/TestDatabase/insert-exec.sql`).** `StarExpander` (Core) takes the text and the caret right after a `*`, accepts it only where it starts a select item (after SELECT, DISTINCT, ALL, TOP n / TOP (n), a comma, or `alias.` / `schema.table.`), finds the sources of the block (`ContextAnalyzer.SourcesAt`, level 0), reads their columns through the same resolution as the list (`SuggestionBuilder.ColumnsOf`: database objects, CTEs, temporary tables, derived tables) and returns the span and text; it returns null when a source is unknown or its columns are not loaded, so Tab stays a normal tab. `ExpandStarHandler` (`ICommandHandler<TabKeyCommandArgs>`, before `default`) runs it only when the previous character is `*`, no list and no snippet session is active; the layout is read at the start of the replaced text so that the columns line up under the first one. Verified: `SELECT * FROM dbo.Customers c JOIN dbo.Orders o …` + Tab gave all columns of both tables with their aliases under each other, `SELECT o.* …` only those of `o`. `ParameterInfoFinder` (Core) finds the call at the caret: the innermost enclosing parenthesis behind a name that is a user function (an unknown name, built-in function, `IN (` or a subquery is skipped and the call around it is used), or an `EXEC [ =] procedure` statement (the current argument by commas, or by name for ` = …`). Function parameters are loaded with the objects (`IDatabaseMetadata.GetFunctionParameters`); procedures as for #44. `ParameterInfoPopup` is a code-only WPF `Popup` (like the list) above the caret line (below when there is no room), signature with the current parameter in bold; typing `(` or `,` shows it (`ICommandHandler<TypeCharCommandArgs>` that shows it after the editor has typed the character), Esc and leaving the call hide it. Facts learned: `ITextCaret.PositionChanged` is raised for caret moves by keys but not when the text is changed (typed, deleted, pasted), so the popup also refreshes on `LayoutChanged`; Ctrl+Shift+Space is taken by SSMS's own parameter info in the SQL editor before the MEF command handlers (an `InvokeSignatureHelpCommandArgs` handler is never called), so the key is bound to our menu command *Parameter Info* in the scope `SQL Query Editor` through `DefaultKeyBindings` (the log says when it was set), which also stops SSMS's own tooltip. Not verified in SSMS: a `*` in a CTE or derived table, the horizontal scrolling of the popup, parameter info on a window with several tabs.
- **INSERT column lists and EXEC parameters (#44, verified in SSMS 22.11 with VSIX 0.20.1, 2026-11-05, test objects in `tests/TestDatabase/insert-exec.sql`).** Metadata: `sys.columns` now also gives `is_identity` and `is_computed` (a rowversion column is recognized by the type name `timestamp`), `DbColumn.IsInsertable` excludes all three; user stored procedures (`sys.procedures`) and their parameters (`sys.parameters`) are loaded with the objects (`IDatabaseMetadata.Procedures`, `DbProcedure`, `DbParameter`). `sys.parameters.has_default_value` is 0 for every T-SQL procedure (it is only set for CLR ones), so the default values come from the text of the procedure: `sys.sql_modules.definition` cut to its first 4000 characters and read by `ProcedureHeader.ReadDefaults` (the lexer; defaults as written, including strings with commas and parenthesized values; a header cut in the middle yields what came before). System procedures (`master`'s `sp_*`) are not offered yet. Contexts (`ContextAnalyzer`): `ObjectName` with `InsertTarget` after `INSERT [INTO]`, `ObjectName` with `ProcedureName` after `EXEC` / `EXECUTE` and `EXEC @r =`, and the new kind `InsertColumns` inside the parentheses of `INSERT INTO table (` (also after a comma). ## MVP

The code is in `src/` and the tests in `tests/`. Build: `dotnet build SqlPrompter.slnx -c Release` on Windows; tests: `dotnet test tests/SqlPrompter.Tests` anywhere. The manual test procedure is in the [README](../README.md).

What the MVP does:

- Keywords at the start of a statement, after a table source (`WHERE`, `JOIN` …) and in expressions; data types after `CAST(x AS` and `DECLARE @x`.
- Tables, views and table-valued functions after `FROM`, `JOIN`, `APPLY`, `UPDATE`, `INSERT INTO`, `DELETE FROM`, `MERGE`, `USING` and `TRUNCATE`/`DROP`/`ALTER TABLE`, also with a schema (`sales.|`). Without a schema they are inserted as `schema.table`.
- Columns of an alias or table (`u.|`, `dbo.Users.|`), and in expressions (`SELECT`, `WHERE`, `ON`, `GROUP BY`, `HAVING`, `ORDER BY`, `SET`) the columns of all sources of the block, aliases and common built-in functions. A column present in several sources is inserted with its alias.
- Query blocks: a subquery in an expression sees the outer query's sources, a derived table and a CTE do not; `UNION` separates blocks. Statements are separated even without semicolons.

Status: runs in SSMS 22.11; the items still to verify are in issue #7.

### Popups are owned and not topmost (verified in SSMS 22, #135)

A WPF `Popup` is hosted in its own top-level window that is topmost, so the completion list, its description panel and the parameter info stayed above other applications. `PopupWindows.Attach` makes the popup window owned by the root window of the editor (`GWLP_HWNDPARENT`) and not topmost (`SetWindowPos` with `HWND_NOTOPMOST`) each time the popup opens. Checked: with the list open, a Notepad window moved over SSMS covers the list and the description panel.

### Restoring tabs on a cold start (#140)

`ScriptFactory` lives in `SQLEditors.dll` (`Extensions\Application`), which SSMS loads only when something needs it. `SsmsConnection.ScriptFactoryType` therefore looks among the loaded assemblies first and then loads `SQLEditors` by name and from its folder. Verified in SSMS 22: a cold start (no query window, the Connect dialog dismissed) restored the saved tab ("Tabs restored: 1 of 1"). The failure of the user's report (type not found) could not be reproduced on the test machine, so the fix is based on the log evidence. SSMS also closes the documents before it announces the shutdown, so an empty list of tabs is saved only when it stays empty for two ticks of the 5 s timer; otherwise closing SSMS could overwrite the saved tabs with an empty list.

### Quick actions on a tap of Ctrl (#125)

`CtrlTap` (created per SQL text view) listens to `PreviewKeyDown` / `PreviewKeyUp` of `view.VisualElement`; modifier-only key presses do arrive there. A tap is a Ctrl key down with no other modifier (not a repeat) followed by its key up while no other key or mouse button came between and `Keyboard.Modifiers` is `None`; in `PreviewKeyUp` of the Ctrl key `Keyboard.Modifiers` already shows `None`. `QuickActionsPopup` is a code-only WPF `Window` (no chrome, owner = the SSMS main window) opened with **`ShowDialog()`**: a modeless window opened with `Show()` never received the keyboard (SSMS routes keys through its own message loop). Its `Deactivated` handler closes it, which must not call `Close()` again while the window is already closing (`InvalidOperationException` in `Window.VerifyNotClosing`, an unhandled exception that **terminates SSMS**); the chosen action runs after the window has closed (`Closed`). The list comes from Core `QuickActionCatalog` (actions for a selection or the whole script, snippets that wrap a selection or not), the filter needs every typed word in the name or description. Verified: Ctrl tap shows the popup under the caret line at the left edge of the editor, filter `brackets` + Enter ran *Remove Square Brackets*. Facts for tests: `keybd_event` (virtual key 0x11) sends a real Ctrl tap; take screenshots without `drive.ps1` while the popup is open, because that script moves the focus and closes it.

**Chords routed to commands (#198).** Keys bound to commands (Ctrl+A, Ctrl+Space) are handled by the shell's command routing and never reach the WPF key events of the editor (see #144), so the events alone saw only Ctrl down and up and counted the release as a tap. Since VSIX 0.71.0 `InputWatcher` installs `WH_KEYBOARD` and `WH_MOUSE` hooks on the UI thread (they see every key, mouse button and wheel turn of the thread, whatever happens to it later) and counts them; `CtrlTapDetector` (Core, unit tested) compares the counter at Ctrl down and Ctrl up and gives a tap only when nothing else happened in between. If the hooks cannot be installed the counter stays 0 and the old key-event logic decides alone. Verified in SSMS 22.11 (2026-11-06, driven with `SendKeys` and `keybd_event`): a tap of Ctrl on its own (left Ctrl with its scan code) opens the popup; Ctrl+A and Ctrl+Space (also repeated, with the other key released first) do not. Also verified (popup detected by its UI Automation items): Ctrl+C, V, X, Z, E, Ctrl+Shift+Space, Ctrl+K Ctrl+C and Ctrl+wheel (repeated Ctrl+A three times) do not open it. Not verified: the build without the hooks (the old behavior), Ctrl+S.

### Resizable completion list (#134)

The list (`SqlCompletionPresenter`) keeps up to 40 prepared rows and shows `visibleRows` of them; a `Thumb` in a 14 px row under the list (a triangle in the bottom-right corner) changes the number of rows (vertical drag / row height) and the width (horizontal drag, 300 to 1600 px). It sits in the non-activating `Popup` and works there: mouse drags are delivered, the editor keeps the keyboard focus, the list stays open and typing continues in the editor. The size is saved on drag completion as `behavior.listRows` (default 12) and `behavior.listWidth` (0 = the width follows the longest item) and is read again each time a list opens, so the settings window (Completion > Size of the list) can change or reset it. Verified in SSMS 22: dragging the corner changed the list from 12 to 17 rows and its width, the list stayed open and typing continued; the values were written to `settings.json`. `CompletionPresenterOptions.ResultingVisibleRows` stays 12 (the broker only uses it for page up/down). A transparent background in the thumb template is needed, otherwise only the drawn triangle can be grabbed. ### Tabs: saving on events and the order of events at shutdown (#168)

`TabSessionService` now also writes the list when a query window is opened or saved (at once), when one is closed (700 ms later) and, as before, every 5 s for the text of unsaved queries; `TabSessionPolicy` (Core) decides whether a write is allowed (never after the shutdown was announced, an empty list at once for a user event and after two empty timer ticks otherwise, never before tabs were seen or restored). The events come from the **running document table** (`IVsRunningDocTableEvents`: `OnAfterFirstDocumentLock`, `OnAfterSave`, `OnBeforeLastDocumentUnlock` with no locks left). DTE `DocumentEvents` were not raised for a window the user closed (they did fire for the windows SSMS closes at shutdown), and neither the WPF `MainWindow.Closing` event nor `WM_CLOSE` / `SC_CLOSE` on the main window were seen when SSMS was closed with Alt+F4. **Order at shutdown (SSMS 22.11, 4 query windows, "Don't Save"):** the *Save changes?* dialog (once, for all unsaved windows), then every window is unlocked in the running document table within about 120 ms (a first unlock with locks left, then the last one), and `DTEEvents.OnBeginShutdown` follows 14 ms after the last unlock. A cancelled shutdown (Cancel in the *Save changes?* dialog) happens before any window is closed, so nothing has to be undone. Verified in SSMS 22 with the test instance: closing a tab by hand removed it from `tabs.json` within a second; closing SSMS (Don't Save) left the file as it was before the burst; a process kill is covered by the event writes (not tried separately). Not verified: closing all tabs by hand and then SSMS right away (the empty list is written 700 ms after the last close), saved files.

### The suggestion list SQL Prompter runs itself (#144)

**Finding:** in SSMS 22.11 a completion session that is started from outside the typing path (`IAsyncCompletionBroker.TriggerCompletion` from a command, with the reason `Invoke` or `Insertion`) calls our `InitializeCompletion` (it returns `ProvidesItems` with the right span), creates a session that is not dismissed, but **never calls `GetCompletionContextAsync`**, so nothing is shown; a session started by typing a letter calls it 3 ms later. The key Ctrl+Space (`Edit.CompleteWord`) reaches neither MEF command handlers (`InvokeCompletionListCommandArgs`, `CommitUniqueCompletionListItemCommandArgs`) nor `PreviewKeyDown` of the editor; the WPF key events of the editor are not given to extensions at all (a Tab pressed while our own list was open was typed into the text), the editor's *command chain* is. A command of ours bound to a key in the scope `SQL Query Editor` does receive the key every time (as Ctrl+Shift+Space for Parameter Info does).
**Solution:** `InvokedList` (one per view) is a small controller that does what the session would not: Ctrl+Space is bound (`DefaultKeyBindings`, once, only if the key is free in that scope) to the new menu command *Show Suggestions*; it asks `SqlCompletionSource.BuildForInvoke` for the items (the same preparation and `SuggestionBuilder` as the session, on the UI thread, never waiting for the database), filters them by the typed text (starts-with first, then contains), shows them in the same popup (`SqlCompletionPresenter.Present` / `Show`, which the session uses too through `Update`), moves the selection with the keys and inserts the choice with the same commit code (`SqlCommitManager.Commit`, now shared: snippets, FROM edit, INSERT/EXEC blocks, functions with parentheses, usage statistics). The keys come from `InvokedListCommands` (command handlers for Down, Up, Page Up/Down, Tab, Enter, Esc and typed characters, before the completion handler; they pass everything on while no such list is open). Where the user probably types a name of their own (soft selection) Enter keeps the text and Tab inserts. **A typed letter closes this list and the editor's own session starts as usual**, so the list only has to cover the moment between the key and the first typed character; a commit character from the settings inserts the choice first. Backspace, Delete and caret moves are noticed through the buffer and caret events and filter again or close the list when the caret leaves the typed text. The window can now be changed independently of the editor's session.
**Also found:** `SuggestionBuilder.ExpressionSuggestions` threw a `NullReferenceException` when the metadata of the database was not loaded yet (the first completion after `USE db`), which the source swallowed into an empty list; keywords, functions and snippets are offered now.
Verified in SSMS 22: Ctrl+Space after `WHERE ty` and `AS a ij` and after `WHERE ` (columns of the table, functions, keywords, scrollbar); Tab inserted the snippet `JOIN` for `ij`; Down + Enter inserted the second item; Esc closed; typing `un` after the list was open handed over to the editor's list with the matching items. Not verified: commit characters (space, dot), Backspace, mouse clicks on rows of this list, a list opened in a window without a connection.

### Column picker and "All non-aggregated columns" (#176)

**Core** (`ColumnClauses`, `ColumnPicker`, tests in `ColumnPickerTests`, 47 cases): `ColumnClauses.At` says whether the caret stands at the start of an item of a select list (after `SELECT`, `DISTINCT`, `ALL`, `TOP n` / `TOP (n)`, `PERCENT`, `WITH TIES` or a comma of the list), of a `GROUP BY` or of an `ORDER BY` (not in `WHERE`, `FROM`, `SET`, `ON`, after `UNION ALL`, inside a function call); `NonAggregatedItems` lists the items of the select list of the same block that a `GROUP BY` has to repeat, as written (aliases of both forms, `AS`, constants, `*`, subqueries, aggregates and window functions are left out; an alias without `AS` is cut unless it would cut an `END`). `CaretContext` now carries the `Text` and `Caret` it was made from. `ColumnPicker.TryBuild` gives the columns of the sources of the block grouped by source (qualified with the alias when there are several sources or the option says so) or, in `INSERT INTO t (...)`, the insertable columns that are not written yet; `Ordered(tableOrder)` is the table order or alphabetical within a source; `InsertText` uses the same layout helper as the expanded `*`. ## Smart suggestions: the position map (#178)

`KeywordMap` (Core, `Analysis`) reads the tokens of the current block before the word being typed (a parenthesized group counts as one token; a caret inside a function call has no position) and says which keywords can follow: `First` (the likeliest), `Then` (possible as well) and `Exclusive` (nothing else can follow: table hints, a CTE). `ContextAnalyzer` stores them in `CaretContext.PreferredKeywords` / `NextKeywords` / `OnlyExpectedKeywords`; `SuggestionBuilder.KeywordSuggestions` ranks them: in the keyword and fallback lists *first* before *then* before the rest; in an expression the keywords of a position after a complete operand (`SELECT a |`, `WHERE x = 1 |`, `CASE … END |`) rank above the columns, the others (`SELECT |`: `TOP`, `DISTINCT`) next to the aliases. Where exactly one keyword can follow (`AS` after a CTE name, `SET` after `UPDATE t`, `ON` after a joined table with its alias) the item is preselected, but only when the typed text is empty or starts that keyword (an alias being typed must not be replaced). Usage ranking still orders items within a group.

**Index DDL (#197).** `IndexDdl` (Core, `Analysis`) holds the positions of `CREATE [UNIQUE] [CLUSTERED | NONCLUSTERED] [COLUMNSTORE] INDEX`, `ALTER INDEX` and `DROP INDEX`. In these statements every position the map knows is a keyword list (kind `Fallback`, or `Keyword` when only the listed words fit), so keywords that do not fit are ranked lower, not hidden. After `ON` tables and views are offered; in the key column list and in `INCLUDE (…)` the columns of the table (`ContextKind.InsertColumns` with `IndexColumns`: all columns, without those already listed, the `INCLUDE` list also without the key columns; the column picker works there too, #200). After `WHERE` the filter predicate is an ordinary expression whose only source is the table of the index (#200). Not covered yet: index names after `ALTER INDEX` / `DROP INDEX` (needs index metadata; #200) and the other DDL statements that still fall back to generic keywords (`CREATE TABLE` column definitions and constraints, `ALTER TABLE ADD` / `ALTER COLUMN`, `CREATE STATISTICS`; #213). Verified in SSMS 22.11 (2026-11-06): after a nonclustered index key list `inc` shows `INCLUDE` first and preselected, then `DISTINCT` and snippets. Not verified in SSMS: the other positions of the table.

**Operators and values in conditions (#204).** In `WHERE`, `AND`, `OR`, `ON`, `HAVING` and `CASE WHEN`, right after a column (`WHERE col |`, `AND a.col |`, also inside parentheses and after `NOT`), `ContextAnalyzer` stores the column in `CaretContext.ConditionOperand` (parts, qualifier first; a reserved word is no column). `SuggestionBuilder` finds the column in the sources of the block and `OperatorSuggestions` (Core) offers the operators that fit its type, each in a group of its own below zero so that their order is kept: `=`, `<>`; `LIKE` and `NOT LIKE` for character types; `<`, `>`, `<=`, `>=` and `BETWEEN` for numbers and dates; `IN` and `NOT IN` (inserted as `IN ()` with the caret between the parentheses); `IS NULL` and `IS NOT NULL` last, or first for a nullable column. A bit or uniqueidentifier column gets neither `LIKE` nor `BETWEEN`. Right after a comparison operator (or `LIKE`) that follows such a column (`AfterComparison`) the values of the type of the column rank first: columns of the same type class (the others move down to the group of outer columns), script variables and parameters of a compatible type, and for a date the functions that return the current date and time. Only metadata and the script are used, never values read from the data. The type class is a plain classification of the type name (`TypeClass`). Verified in SSMS 22.11 (2026-11-06): after `WHERE Name ` and a typed `l` the list shows `NOT LIKE`, `IN`, `NOT IN`, `IS NULL`, `IS NOT NULL` above the columns. Also verified (VSIX 0.73): `IN` + Tab inserts `IN ()` with the caret inside (typing `5` gives `IN (5)`) because the plain keywords the operator items cover are not offered again; after `WHERE Created >= ` and `g` the date functions `GETDATE`, `GETUTCDATE`, `SYSDATETIME`, `SYSUTCDATETIME` come first, after the `Created` column.

**INSERT and MERGE fragments (#205).** `StatementFragments` (Core) adds whole fragments in front of the keywords, as block items (`IsBlock`, group -1): after `INSERT INTO t (a, b) |` (`CaretContext.InsertTail` / `InsertTailColumns`, found by `TryInsertTail`) `VALUES (...)` with a value by type per listed column (`SqlDefaults`, laid out by the insert layout setting) and `SELECT a, b` + `FROM `; in a MERGE (`CaretContext.Merge`: the stage is read from the keyword position, `Sources` are now also set on the keyword contexts) after `USING source |` the `ON` condition from `JoinSuggestions.Conditions` (foreign key, or columns of the same name), and after the condition or a WHEN action `WHEN MATCHED THEN UPDATE SET ...` (shared columns except the primary key, laid out by the formatting style), `WHEN NOT MATCHED THEN INSERT (...) VALUES (...)` and `WHEN NOT MATCHED BY SOURCE THEN DELETE`. Identity, computed and rowversion columns are never generated. Not done yet: the column picker for `UPDATE ... SET` (follow-up issue). Verified in SSMS 22.11 (2026-11-06): `INSERT INTO dbo.Users (Name, Email) val` + Tab on `VALUES (...)` inserts `VALUES (N'', NULL)` laid out on lines; after `USING dbo.Staging AS s` the list offers `ON t.Email = s.Email` and the other same-name conditions; after the `ON` condition `WHEN MATCHED THEN UPDATE SET ...` (comma-before style), `WHEN NOT MATCHED THEN INSERT ...` and `WHEN NOT MATCHED BY SOURCE THEN DELETE` commit as whole clauses and rank above the keywords; names keep their case when the keyword case is forced. Also verified: `SELECT ... FROM` after the INSERT list inserts `SELECT Name` / `, Email` / `FROM ` laid out by the style.

**Window functions (#215).** `Keywords.RequiresOver` / `IsRankingWithoutArguments` / `IsWindowFunction` classify the ranking and analytic functions (`ROW_NUMBER`, `RANK`, `DENSE_RANK`, `PERCENT_RANK`, `CUME_DIST`, `NTILE`, `LAG`, `LEAD`, `FIRST_VALUE`, `LAST_VALUE`) and the aggregates. After the call of a function that needs `OVER` (`SELECT ROW_NUMBER() |`) `OVER` is the only preferred keyword and is preselected. The function list has an extra item for each window function that inserts the call with `OVER (PARTITION BY  ORDER BY )` and puts the caret in the first slot (the argument, or after `PARTITION BY` for the functions without argument) by `CaretBack`; there are no tab stops between the slots yet (a snippet-like session would be needed), and parameter info for the window functions is not done. Verified in SSMS 22.11 (2026-11-06): `row_n` offers `ROW_NUMBER` and `ROW_NUMBER() OVER (...)`; the second inserts `ROW_NUMBER() OVER (PARTITION BY  ORDER BY )`. Also verified: after `SELECT ROW_NUMBER() ` and Ctrl+Space `OVER` is first and preselected; after committing `ROW_NUMBER() OVER (...)` the caret is after `PARTITION BY `.

**Correlated subqueries (#216).** For the first table of a subquery that has outer queries (`FROM |` after `EXISTS (SELECT ...`, `IN (SELECT ...`, `CROSS APPLY (SELECT ...`; `CaretContext.CorrelatedFrom`, set when the block has no table of its own besides the word being typed) `JoinSuggestions.Build(correlated: true)` offers the tables connected by a foreign key to a table of an outer query first (same group as after `JOIN`), inserted with the alias and without `ON`, the foreign key name on the right and the condition in the detail. After the table and its alias (`CaretContext.Correlation`) `StatementFragments` offers `WHERE <condition>` from `JoinSuggestions.Conditions` with `Correlated` set, which lets the conditions reach the tables of the outer queries (foreign key, or same column names). Not done: the column matching the compared outer column in `IN (SELECT |`. Verified in SSMS 22.11 (2026-11-06, test database with Orders, OrderItems, Payments): in `SELECT * FROM dbo.Orders o WHERE EXISTS (SELECT 1 FROM p` the list starts with `OrderItems` and `Payments` with `o.IdOrder = oi.IdOrder` / `FK_...` on the right; after `FROM dbo.Payments AS p ` the first item is `WHERE o.IdOrder = p.IdOrder`.

**Loose matching of names (#219).** `NameMatcher` (Core) is the one matching function behind `ListOrdering.Filter` / `Matches` and the highlighting of the list SQL Prompter runs itself (invoked list, picker, the optional typing controller). A match has a kind, ranked in this order: exact, prefix, *words* (the typed text starts at word beginnings: CamelCase humps, after `_ - . space`, the end of an acronym; `BKT`, `BuKl`, `kt` for `Burza_Klient_Typ`), substring, *subsequence* (the characters in order, `bzkl`); within a kind the order of the input (group, usage, name) is kept. A cheap in-order check rejects most names first; 50,000 names are filtered in far less than the 50 ms target on a normal machine (the unit test allows 500 ms). The matched characters are highlighted (`NameMatch.Runs`). The option *Match initials and loose characters* (Tools > Options > SQL Prompter > Completion, default on) switches the loose kinds off (`BehaviorSettings.LooseMatching`). The editor's own session (typing with the built-in list controller) filters with the platform's matcher, which already does CamelCase but no arbitrary subsequence; it is unchanged. Verified in SSMS 22.11 (2026-11-06): with `SELECT * FROM bkt` and Ctrl+Space the invoked list shows `BurzaKlientTyp`, `Burza_Klient_Typ2` (words) and `BukettBook` (subsequence), the matched letters in bold. Not verified: the option in the settings window.

**HAVING and ORDER BY (#214).** `ColumnClauses.ShapeOf` (Core) describes the block the caret is in: the items of its select list (expression as written, alias, aggregate or not, star), the expressions of its `GROUP BY` and `DISTINCT`. `SelectListSuggestions` adds, in front of everything else (a group of its own for each item, from -100 up, so that the order of the select list is kept; the sort text of a group is `group + 100`, so the groups must not go below -100): after `HAVING`, `AND`, `OR`, `NOT` (`CaretContext.InHaving`) the aggregates of the select list as written (`COUNT(*)`, `SUM(Total)`; not the alias, which HAVING cannot use); after `ORDER BY` and after a comma in it the aliases (or the expressions) of the select list, no `*`. With a `GROUP BY` before the caret only the grouped columns and without one but with `DISTINCT` only the columns of the select list stay among the columns of the ORDER BY list (the test is the name, also when written `o.UserId`). Not done: `UNION` (the columns of the first select only), `OFFSET ... FETCH`, `OPTION` and `FOR XML/JSON` after the last item (the keyword positions of #178 stay), and the aggregates inside a parenthesized HAVING condition. Verified in SSMS 22.11 (2026-11-06): after `... GROUP BY IdUser HAVING ` and Ctrl+Space the list starts with `MAX(Qty)`, `COUNT(*)` (case kept) ahead of the columns, functions and the like; after `SELECT IdOrder AS Ord, Qty * 2 AS Dbl, Qty FROM dbo.OrderItems ORDER BY ` it starts with `Ord`, `Dbl`, `Qty` in the order of the select list; with `GROUP BY IdOrder` only `Cnt`, `IdOrder` and the grouped column remain.

Cases are in `KeywordMapTests`, `KeywordMapMoreTests`, `IndexDdlTests`, `OperatorSuggestionTests`, `StatementFragmentTests`, `WindowFunctionTests`, `CorrelatedSubqueryTests`, `NameMatcherTests` and `HavingOrderByTests`. A position unknown to the map keeps the old behavior (all keywords, with those the analyzer preferred before first). Not covered yet: the clauses of `CREATE TABLE` / `ALTER TABLE`, `EXEC` parameter names (offered elsewhere), `FETCH` of cursors, `FOR` after `DECLARE … CURSOR`. Verified only by unit tests (and four positions in SSMS 22) until the user tests the VSIX.
**ALTER of a module (#203).** After `ALTER PROCEDURE | PROC | FUNCTION | VIEW | TRIGGER` (also `CREATE OR ALTER` and `DROP`) the context is `ObjectName` with `Module` / `ModuleAction` / `ModuleHeaderStart` set and the list holds only modules of that kind (no snippets, no keywords): procedures and (user) views and functions from the snapshot, triggers from the new `IDatabaseMetadata.Triggers` (`DbTrigger`: schema, name, parent as `schema.table`; database DDL triggers have none), read by the last result set of the objects query (`sys.triggers`, checked against the Docker test instance). `ALTER` and `CREATE OR ALTER` items carry a `ModuleScript` (`Suggestion.Tag`). In the SSMS layer the commit (`SqlCommitManager`) inserts the name at once, then `ModuleScriptInserter` loads the definition in the background (`DefinitionPreview.Request`, never waiting on the UI thread) and replaces the text from the start of the statement (a tracking point) to the end of the name with `DefinitionScript.ToAlter` (the first `CREATE`, with its `OR ALTER`, becomes `ALTER`; comments, case and the rest are kept; `SET ANSI_NULLS` lines are not added). The caret goes to the line after the first `AS` of the header (`DefinitionScript.BodyStart`). If the text was edited meanwhile, or there is no script (encrypted, no `VIEW DEFINITION`), the name stays and the status bar says why. `DROP` items insert the name only. Verified in SSMS 22.11 (2026-11-06, test database with a table, view, procedure, DML trigger and function): `ALTER TRIGGER tr` + Tab, `ALTER PROCEDURE get` + Tab, `ALTER VIEW act` + Tab and `CREATE OR ALTER FUNCTION fnU` + Tab replace the typed text with the whole current definition (`ALTER`, resp. `CREATE OR ALTER`), the status bar says "inserted the definition of ..."; `DROP VIEW act` + Tab inserts `dbo.ActiveUsers`. Also verified: for `ALTER PROCEDURE` the caret lands at the start of the line after the `AS` of the header; an encrypted procedure keeps just the name. Not verified: a module without permission, a text edited while loading. Not covered: `ALTER TABLE |`, `ALTER SEQUENCE |`, `DROP TABLE |` (name-only lists of one kind) and database DDL triggers' scripts (they are not found by `DefinitionLoader`, so only the name is inserted).

Cases are in `KeywordMapTests`, `KeywordMapMoreTests`, `IndexDdlTests` and `AlterModuleTests`. A position unknown to the map keeps the old behavior (all keywords, with those the analyzer preferred before first). Not covered yet: the clauses of `CREATE TABLE` / `ALTER TABLE`, `EXEC` parameter names (offered elsewhere), `FETCH` of cursors, `FOR` after `DECLARE … CURSOR`. Verified only by unit tests (and four positions in SSMS 22) until the user tests the VSIX.

**Snippets** are offered in every position (not after a qualifier and not in a name that is being invented): those whose prefix starts with the typed text in group 1 (next to the aliases), all the others (those that contain it and, before a character is typed, all) in the last group (`SuggestionBuilder.SnippetsLastGroup`, 50). Usage ranking takes precedence: a snippet that was chosen before is sorted as if it were in group 1 and, within the group, by the number of uses (`Suggestion.RankedSortText`).

## Compatibility gate (#186)

`SsmsCompatibility` (Ssms) probes at start, on the UI thread and before the tabs are restored, everything undocumented that SQL Prompter relies on; the list of requirements, their features and the report are in Core (`CompatibilityRequirements`, `CompatibilityReport`, tests in `CompatibilityTests`). A requirement that is not found (a probe returns text or throws) switches off only the features that need it: `ActiveConnection` (the connection of the window: metadata, history, tab colors), `OpenWindow`, `RestoreTabs`, `ResultsGrid`, `ExecuteHook` (metadata refresh after DDL, execution warnings, history) and `WordKeys` (Ctrl+Left/Right pass-through). The log gets the build and every missing requirement, and the user is told once per outcome (the SSMS build and what is missing; remembered in `%LOCALAPPDATA%\SqlPrompter\compatibility.txt`) by a message box. Requirements (12): `ScriptFactory` type, `Instance`, `CurrentlyActiveWndConnectionInfo`, `UIConnectionInfo` type, its properties `ServerName`/`UserName`/`AuthenticationType`/`AdvancedOptions`, its parameterless constructor, `CreateNewBlankScript(…, UIConnectionInfo, …)` and the DTE commands `Edit.CopywithHeaders`, `Query.Execute`, `Query.Disconnect`, `Edit.WordPrevious`, `Edit.WordNext`. A new undocumented dependency is added to `CompatibilityRequirements` and to the probe.

**Tested SSMS build: 22.11.12328.437** (all 12 requirements found, verified 2026-11-06). The environment variable `SQLPROMPTER_SIMULATE_MISSING` (ids separated by commas) makes the probe report requirements as missing, to try the gate: with `Command.Edit.CopywithHeaders,ScriptFactory.CreateNewBlankScript` the log said "10 of 12 … found" and switched off opening windows, restoring tabs and the grid actions; a message box with the build and the switched-off features appeared once. The smoke script `.claude/skills/drive-ssms/smoke.ps1` (run after an SSMS update) checks the compatibility line of the log and makes screenshots of four completion scenarios (`drive.ps1` cannot read the items of our own list through UI Automation any more, so they are judged by looking). Not covered by the gate: the tab color view model members (`TabAccentBrush`, `IsTabGroupColorized`, `IsActive`) that are found on a tab object at runtime.

## The list for typing through our own controller (#187, step 1)

The option *Run the list myself while typing (experimental)* (`behavior.ownTypingList`, default off; Settings → Completion) makes the list that opens while typing the same list as Ctrl+Space (`InvokedList`) instead of the editor's completion session. How it works:

- `InvokedListCommands` is now a chained handler of `TypeCharCommandArgs`: it first offers the character to an open list (`OnTypedChar`: a commit character inserts the selected item), then lets the editor insert it (`nextCommandHandler`), and then, if no list is open and the character can start a list (`SqlCompletionSource.StartsList`, the same characters as the session's `IsTrigger`), calls `InvokedList.OpenForTyping`.
- `SqlCompletionSource.BuildForTypingAsync` prepares on the UI thread with the same rules as the session (`Initialize(…, out Prepared)` no longer shares the `pending` field with the session) and builds the items on a background thread (`Task.Run`, sorted by `ListOrdering`); the result is dropped when the user has typed more in the meantime (the newest request wins).
- With the option on, the editor's session still takes part for a typed character (so that the built-in list does not show) but offers nothing (`ProvidesItems` with an empty span, as while a snippet field is typed).
- A list opened by typing (`typingMode`) stays open while letters are typed: the typed text is part of its span, the text buffer change filters again (`ListOrdering.Filter`), and Backspace / caret moves close it when the caret leaves the span. Esc, Up/Down, Tab and Enter work as in the Ctrl+Space list; the status bar with the column picker is the same.

Verified in SSMS 22.11 (VSIX 0.60.0): after `dbo.` the list opens; `ca` filters it to Categories and Tab inserts `Categories AS c`; `SELECT na` shows `Name` with the matching part in bold and the matching snippets at the end; Backspace shows all items again; Down + Enter insert the second item. Not verified yet: IME, very fast typing, snippet fields, comma/space triggers, the picker after typing (checklist in #187).
