# SQL Prompter: architecture

An extension with custom IntelliSense for SQL Server Management Studio 22.

**Status:** the prototype answered all three questions in SSMS 22.11 (see [Prototype](#prototype)). The MVP runs in SSMS 22.11 (see [MVP](#mvp)). What comes next is planned in the GitHub issues.

## Summary

C# and a classic VSIX extension running in the SSMS process. All logic lives in libraries that do not depend on SSMS; the SSMS layer is as thin as possible.

## Main risk

Microsoft states that third-party extensions are not supported in SSMS. SSMS does not block them, but closes reports about them without investigation ([SSMS FAQ][faq]). An SSMS update may break the extension at any time.

## Technology

| Layer | Choice | Reason |
|---|---|---|
| Language | C# | Native language of the editor API |
| SSMS add-in | .NET Framework 4.8, AnyCPU | SSMS is 64-bit and also exists for Arm64 ([FAQ][faq]) |
| Core | .NET Standard 2.0 | Builds and tests also outside Windows |
| Editor integration | MEF and `IAsyncCompletionSource` ([walkthrough][completion]) | Modern API with background computation |
| Metadata | Queries on `sys.*` through `System.Data.Common`, connection from the `Microsoft.Data.SqlClient` in the SSMS process | Fast, read-only, no SMO dependency and no second SqlClient copy |

SSMS 22 is built on Visual Studio 2026 ([FAQ][faq]). According to [another extension author's notes][sqlfluff], `Microsoft.VisualStudio.SDK` 17.14 is used because there is no 18.x package. The prototype confirmed this in SSMS 22.11.

VisualStudio.Extensibility is not used: no document confirms support in SSMS, and according to [the same source][sqlfluff] replacements for parts of the editor API are missing.

## Structure

```text
┌──────────────────── SSMS 22 process ────────────────────┐
│  SqlPrompter.Ssms (VSIX, thin layer)                     │
│  completion · commit · settings                          │
│  current connection                                      │
│        │ own interfaces, no SSMS types                   │
│  ┌─────▼──────────────┐   ┌──────────────────────────┐   │
│  │ SqlPrompter.Core   │◄──│ SqlPrompter.Metadata     │   │
│  │ lexer              │   │ per-database cache       │   │
│  │ context analysis   │   │ background loading       │   │
│  │ suggestion ranking │   └────────────┬─────────────┘   │
│  └────────────────────┘                │                 │
└────────────────────────────────────────┼─────────────────┘
                                         ▼
                                    SQL Server (sys.*)
```

| Project | Target | May depend on |
|---|---|---|
| `SqlPrompter.Core` | netstandard2.0 | Nothing from VS, SSMS or a database |
| `SqlPrompter.Metadata` | netstandard2.0 | Core and `System.Data.Common`; the host supplies the concrete `DbConnection` |
| `SqlPrompter.Ssms` | net48, VSIX | VS SDK, SSMS API, both projects above |
| Tests | Current .NET | Core and Metadata, cases like `SELECT u.| FROM dbo.Users u` with the caret marked |

## Completion flow

1. On the UI thread (`InitializeCompletion`) the batch between `GO` lines is extracted, tokenized and the context determined, e.g. "column of alias `u`".
2. In the same step, missing metadata is identified and loaded in the background.
3. In the background (`GetCompletionContextAsync`) suggestions are built and ranked from the context and the current snapshot.

This flow never waits for the database. Metadata starts loading when a query window is activated, and the columns of user objects are loaded together with the objects, so they are usually ready before the user needs them. Whatever is missing (columns of system views, the very first load) is added on the next completion. The 1 s timer of `TabColoring` also calls `MetadataService.CacheForActiveWindow`, so switching the database in the toolbar drop-down starts the load of that database at once (verified in SSMS 22.11: the active connection info follows the drop-down). Until a snapshot is there the list starts with a "Loading the objects of <database>..." row (a "Could not load ..." row with the reason after a failure; `DatabaseMetadataCache.Status`), and the open list is made again when the load finishes or fails (`SnapshotReplaced` / `LoadFailed` go through `MetadataService.LinkedServerLoaded`, the same path as the linked server loads, #357); a failed load is retried by the timer after `RetryDelay` (30 s). Every database has its own cache, so a late result never fills the list of another database (#470). Objects defined in the script (CTEs, temporary tables, table variables, variables, parameters) come from the script model, see below.

## Decisions

- **Two parsers.** While typing, SQL is almost always incomplete, so completion uses its own tolerant lexer and a light clause analysis. Microsoft ScriptDOM is used for full analysis of valid statements (formatting, refactoring, diagnostics). ScriptDOM is [open source under the MIT license](https://github.com/microsoft/sqlscriptdom) and supports netstandard2.0 (verified 2026-11-02).
- **Not based on `Microsoft.SqlServer.Management.SqlParser`.** It is [not open source][sqlparser] and its license terms are not verified.
- **Metadata as immutable snapshots.** Every database has its own snapshot. Columns of user objects are loaded with the objects, columns of system views on demand. Refresh by `sys.objects.modify_date`, after DDL in the window and by a manual command.
- **Security.** Passwords are never stored. Metadata goes to disk only optionally, because even object names may be sensitive. No telemetry.
- **Target performance (draft).** Under 50 ms for a list from the cache and no waiting for the network on the UI thread.
- **Only our list.** Our participation suppresses the built-in list (prototype, question 2). The user wants to see only SQL Prompter's suggestions (decided 2026-11-02), so the extension participates everywhere except in strings, comments and numbers. The built-in IntelliSense stays enabled for error underlining and quick info.
  - Where a new or unknown name is typed (alias after `AS`, a variable being declared, `#table` outside a table position, unknown qualifier, three-part name), the list is empty.
  - After `@`, the variables and parameters defined in the script are offered (`ContextKind.Variable`).
  - After `CAST(x AS` and `DECLARE @x`, data types are offered.
  - At positions the extension does not understand (`EXEC`, `VALUES`, `SET @x =` …), keywords, functions and types are offered without a firm selection.
  - With a CTE, derived table, temporary table or table variable, the columns of known sources, aliases and functions are offered.
  - Suggestions carry the "SQL Prompter" filter, which makes the list recognizable.
  - Not verified yet: whether an empty list really suppresses the built-in one.
- **Script model** (`ScriptModel` in Core, implemented in #15, verified in SSMS 22.11 on 2026-11-05). Definitions in the batch before the caret, built from text only and in the background (`GetCompletionContextAsync`), so the UI thread is not slowed down:
  - CTEs of the statement at the caret, `#tables` from `CREATE TABLE` and `SELECT … INTO`, `@tables` from `DECLARE @t TABLE`, variables from `DECLARE`, and the parameters of `CREATE/ALTER PROCEDURE/FUNCTION`;
  - columns of a CTE, `SELECT … INTO` table or derived table come from the first `SELECT` of its query (alias, `AS`, `alias = expr`, last part of `a.b`, `x.*` and `*`); `SELECT *` is expanded from the metadata snapshot and the objects whose columns are not loaded yet are requested in the background (`ScriptColumns.MissingColumns`);
  - items without a name (`SELECT 1`) are skipped, and only the first block of a `UNION` names the columns;
  - the model is never trusted for what it cannot see: a source it cannot resolve stays unknown, as before.
- **SqlClient from the SSMS process.** Our own connection creates `Microsoft.Data.SqlClient.SqlConnection` from the copy SSMS has loaded (verified by the prototype, version 6.0.0.0). The VSIX ships no SqlClient and Metadata works with `DbConnection` only. The SqlClient 6 package does not support netstandard2.0 anyway.
- **System objects.** Metadata is read from `sys.all_objects` and `sys.all_columns`, so `sys.objects` or `INFORMATION_SCHEMA.TABLES` work as in the built-in IntelliSense. System objects are not offered without a schema.
- **Commit keys.** As in the user's SQL Prompt settings: Tab, Enter and Space insert the suggestion; a dot, comma, parenthesis, semicolon, `]` or operator does not (`CommitKeys` in Core, configurable in Tools → Options → SQL Prompter → Behavior since 0.3.0, #9). Every character that ends a word must still end the session: when only Tab and Enter were commit characters, the list stayed open after a space or a dot (verified in SSMS 22.11). The commit manager therefore reports non-inserting characters as a handled commit without inserting anything, so the list closes, the character is typed and a dot opens the next list (verified in SSMS 22.11). Where the user probably types a name of their own (after a table source or an operand), the selection is soft (`SoftSelection`) and typed characters do not commit. Keywords are inserted in lower case when the user started typing in lower case.
- **Metadata refresh in the MVP.** At most once every 30 s, completion checks a fingerprint of `sys.objects` (count and latest `modify_date`) and reloads the snapshot after a change. The manual command SQL Prompter → Refresh Metadata drops all snapshots instead.
- **Refresh after DDL in the window (#8).** The package subscribes to `BeforeExecute` of the DTE command `Query.Execute` and takes the selection, or the whole document, of the active window. `SchemaChangeDetector` (Core, lexer-based, ignores comments and strings) recognizes `CREATE`/`ALTER`/`DROP` of tables, views, procedures, functions, triggers, schemas, synonyms, types and sequences, `sp_rename` and `SELECT … INTO`. If it finds one, the fingerprint is checked 1, 3, 10 and 30 s later regardless of the 30 s interval, because execution is asynchronous and the event fires before it ends. Verified against SQL Server 2025: the fingerprint changes after `CREATE TABLE`, `ALTER TABLE … ADD` and a column `sp_rename`. Verified in SSMS 22.11: the watcher finds `Query.Execute` and the log shows the snapshot refreshed after DDL ran in the window.
- **Verified in SSMS 22.11 with VSIX 0.6.1 (2026-11-04), driven by Claude through UI Automation.**
  - Every item of the list shows "SQL Prompter" in its suffix (#20).
  - `USE db` on an earlier line makes completion use that database although the window is connected to `master`; the log shows the metadata of that database loading (#25). The first completion after a database is first used is empty, the next one has its objects (loading is in the background).
  - `Db.`, `Db..` and `Db.dbo.` offer the objects of the other database, a synonym is offered like a table and its columns come from the target (#25).
  - Choosing a table after `FROM` inserts `dbo.OrderItems AS oi`; columns are inserted as `u.Email` (#23).
  - `SELECT em` without `FROM` offers `Email (Users)`; choosing it gives `SELECT u.Email FROM dbo.Users AS u`, also with `, Name WHERE 1 = 1` after the caret (the `FROM` goes before `WHERE`) (#24). The commit manager must compute the caret position from `span.Start.Position`: `span.Start + n` throws on the replaced snapshot and the default commit then inserts the text a second time.
  - Not verified yet: the options pages, Export and Import Settings, custom aliases, ignored prefixes and the keyword case option.
- **Driving SSMS from a script.** `SSMS.exe -S localhost,1433 -U claude -d master -C -N Optional` shows a confirmation dialog and a login dialog without a password (`-P` is not accepted). `System.Windows.Automation` finds them: invoke "Yes", then set the Password edit through `ValuePattern` and invoke "Connect". The editor is the `Edit` named "Text Editor": `SetFocus`, paste text through the clipboard (no completion triggers) and `SendKeys` for typing. The completion list is a `ListBox` of `IntellisenseMenuItem` elements whose `Text` children hold the name and the suffix; the editor text is readable through `TextPattern`. Killing SSMS with an unsaved window shows a recovery dialog on the next start ("Do Not Recover"); close it with Alt+F4 and "Don't Save" instead.
- **Linked servers (#26, verified in SSMS 22.11 with VSIX 0.8.1; test linked server `SqlPrompterLS` to the Docker instance itself, created with a provider string `Encrypt=Optional;TrustServerCertificate=Yes;UID=…;PWD=…` because the test login cannot create login mappings).** The first load only adds `SELECT name FROM sys.servers WHERE is_linked = 1`, so the initial load does not depend on what is behind the servers. `Srv.` offers the databases (`EXEC sp_catalogs @server_name`), `Srv.Db.` its schemas and objects (`EXEC sp_tables_ex @table_server, @table_catalog`: several hundred rows including system objects, flagged as such, takes a few seconds), `Srv.Db.schema.` and `Srv.Db..` the objects of a schema, and a four-part source such as `Srv.Db.dbo.T t` gets its columns from `EXEC sp_columns_ex` when `t.` is typed. `LinkedServerCache` (Metadata) never waits: it returns what is cached, starts the load in the background (15 s command timeout, 30 s overall) and remembers a failure for 60 s; the first completion after choosing a server or database is therefore empty and the next one has the names. A schema or database of the current database wins over a linked server of the same name. A server that cannot be reached (`BadLS` without a login mapping) only logs "Linked server: loading … failed" and the normal list keeps working. Columns of remote tables carry the type from `TYPE_NAME` with the size, and `NULLABLE`.
- **Keys and JOIN suggestions (#28, verified in SSMS 22.11 with VSIX 0.9.1).** The first metadata load now also reads `sys.foreign_keys` with their column pairs (`sys.foreign_key_columns`, in column order, so multi-column keys keep their order) and the primary keys (`sys.indexes.is_primary_key`); the DDL refresh brings them with the rest because constraints change the `sys.objects` fingerprint. After `JOIN` the tables that have a key to a table of the query, or that a table of the query points to, come first (group −1, sort key "-01") as one item with the whole clause, e.g. `Doprava ON d.IdObjednavka = p.IdObjednavka AND d.IdPolozka = p.IdPolozka`, inserted as `Crm.Doprava AS d ON …`; the name of the key is the suffix and two keys between the same tables give two items. The new table stands left of the `=` for now (the option for the order is #29). The word being typed is parsed as a table source of its own, so it is not counted as a used alias. Columns carry a key kind and the custom list shows a key icon after the type (primary key wins over foreign key). Icons of the custom list are themed with `ImageThemingUtilities.SetImageBackgroundColor` and the theme background (without it they are drawn dark); the list width is estimated from the longest row (420 to 1000 DIPs).
- **Conditions after ON (#29, verified in SSMS 22.11 with VSIX 0.10.0).** At the start of a condition after `ON` (or `AND` / `OR` following it) the analyzer sets `JoinTarget`, the table introduced by the JOIN whose ON is being edited (found through the token index of the source that follows the nearest `JOIN` before the `ON`; the sources parse the whole block, so `JOIN a ON | JOIN b` still finds `a`). `JoinSuggestions.Conditions` links it to every table before it in the query: the whole foreign key (columns joined by `AND`), with the option every single column pair of a multi-column key, then conditions for column names both tables have (those that are a key column in one of the tables before the others), skipping what a key already covers. They are items of the new kind `JoinCondition` (own icon) and sort before everything else: negative groups −4 to −1, which needed the sort key to be `(Group + 100)` as three digits, because the old `Group.ToString("D2")` put "-01" before "-04". Options page *Joins*: new table on the left (off by default: the user's SQL Prompt has "Swap order of columns in join clauses" on, which puts the new table on the right, `u.IdUser = o.IdUser`, while SQL Prompt's own default is `table2.id = table1.id`; confirmed from the user's screenshot of that option), single columns of multi-column keys, columns with the same name, same name needs the same type. The SQL Prompt import takes `IncludePartialFKJoinConditions`, `AlwaysIncludeNameMatchedJoinConditions` and `FlipColumnsOnJoinCondition`; `FlipColumnsOnJoinCondition` (swap) is imported as "new table on the left" = not swap. SQL Prompt's "always include type-matched conditions" (columns of the same type with different names) is not imported or implemented.

Only the active tab is checked, so a tab is colored once it has been active in this session (a restored window gets its color when first selected). - **Editor helpers (#52, verified in SSMS 22.11 with VSIX 0.25.9, 2026-11-05).** Core (Editing): LineTools (add commas: every line with text except the last gets a comma; add quotes and commas: each line becomes 'text' with ' doubled, the last without a comma; indentation, blank lines and line breaks are kept), AutoClose.Decide (from the lexer: nothing is closed inside strings, comments and bracketed names, before a word character, after a word character except the N prefix, or next to another quote; typing the closing character that is already there steps over it) and MatchFinder (same name ignoring case and brackets; keywords, strings and comments never match; a name that appears once is not marked). - **Ranking by usage (#47, verified in SSMS 22.11 with VSIX 0.24.0, 2026-11-05).** `UsageStatistics` (Core) counts how often an item was chosen: a key is the database plus `Suggestion.UsageKey` (kind, text, suffix, e.g. `Table|Orders|dbo`); at most 5000 keys (the least used are forgotten down to 90 %), JSON as a list of `{key, count}`, a broken file gives empty statistics. Within a group the editor's sort text is `group` + `UsageStatistics.SortPrefix(count)` + text (`Suggestion.RankedSortText`): more used first, counts above 998 equal, never-chosen items keep the alphabetical order, and the group still wins (a column stays above a keyword however often the keyword was chosen). `UsageService` (SSMS) loads `%APPDATA%\SqlPrompter\usage.json` in the background at start (what is chosen before that is merged in), `SqlCommitManager` records the key of every item inserted by a commit key (Enter, Tab, Space …), and the file is written 5 s after the last change through a temporary file. *Rank by usage* (`behavior.rankByUsage`, on by default) switches it off; *SQL Prompter → Reset Usage Statistics* (menu version 10) asks and clears memory and file. Verified: choosing `Orders` twice and `fnOrdersOf` once made the list after `FROM` start with `Orders`, `fnOrdersOf`, then `Customers` (alphabetically `Customers` would be first), and the file held both counts. Not verified: the reset command through the menu, a very long usage file, the list when the setting is switched off at run time (the sort text is chosen per item when the list is built, so it applies from the next list on).

An open list is made again when a snapshot has arrived. Verified: columns after the alias of such a table, the hover over the table name shows the columns, key and `CREATE TABLE` script of the other database. Not verified: a database the login cannot open (the failure text), F12 on the alias, `Db..table`, a synonym that points into another database, the JOIN suggestions and the code analysis for such tables (they do not know those columns yet).
- **Object definition next to the list (#46, verified in SSMS 22.11 with VSIX 0.23.1, 2026-11-05, test objects in `tests/TestDatabase/insert-exec.sql`).** A suggestion for a table, view, table-valued or scalar function or procedure carries the object it stands for (`Suggestion.DefinitionSchema` / `DefinitionName`; none for synonyms, schemas, keywords, columns). The completion source puts it on the item as `DefinitionRef` (database of the metadata, schema, name) only for a `DatabaseSnapshot` (nothing for linked servers). The presenter keeps one `Popup` for the description and shows the script in it under the description, monospaced: `DefinitionPreview` reads the script with the F12 `DefinitionLoader` (new connection, 10 s timeout, in the background through `JoinableTaskFactory`) and keeps it for two minutes, per connection, database and object; the presenter asks for it 300 ms after the selection stops on an item (a `DispatcherTimer`, cancelled when the selection moves on, so scrolling through the list asks for nothing) and shows a cached script at once. Only the first 28 lines (lines cut at 110 characters) are shown. Verified: the selected procedure shows its `CREATE OR ALTER PROCEDURE` with parameters and body, a table its `CREATE TABLE` with the primary key constraint, the list stayed responsive while the script loaded. - **Expanding * and parameter info (#45, verified in SSMS 22.11 with VSIX 0.22.0, 2026-11-05, test objects in `tests/TestDatabase/insert-exec.sql`).** `StarExpander` (Core) takes the text and the caret right after a `*`, accepts it only where it starts a select item (after SELECT, DISTINCT, ALL, TOP n / TOP (n), a comma, or `alias.` / `schema.table.`), finds the sources of the block (`ContextAnalyzer.SourcesAt`, level 0), reads their columns through the same resolution as the list (`SuggestionBuilder.ColumnsOf`: database objects, CTEs, temporary tables, derived tables) and returns the span and text; it returns null when a source is unknown or its columns are not loaded, so Tab stays a normal tab. `ExpandStarHandler` (`ICommandHandler<TabKeyCommandArgs>`, before `default`) runs it only when the previous character is `*`, no list and no snippet session is active; the layout is read at the start of the replaced text so that the columns line up under the first one. Verified: `SELECT * FROM dbo.Customers c JOIN dbo.Orders o …` + Tab gave all columns of both tables with their aliases under each other, `SELECT o.* …` only those of `o`. `ParameterInfoFinder` (Core) finds the call at the caret: the innermost enclosing parenthesis behind a name that is a user function (an unknown name, built-in function, `IN (` or a subquery is skipped and the call around it is used), or an `EXEC [ =] procedure` statement (the current argument by commas, or by name for ` = …`). Function parameters are loaded with the objects (`IDatabaseMetadata.GetFunctionParameters`); procedures as for #44. `ParameterInfoPopup` is a code-only WPF `Popup` (like the list) above the caret line (below when there is no room), signature with the current parameter in bold; typing `(` or `,` shows it (`ICommandHandler<TypeCharCommandArgs>` that shows it after the editor has typed the character), Esc and leaving the call hide it. ## Prototype

**Question 1: yes.** The MEF extension loads and `IAsyncCompletionSource` works in the SQL editor: typing `hel` offers `hello`.

**Question 2: yes, no duplicates.**

- Control test with `SELECT * FROM sys.ob`: with `hello` turned off the built-in SSMS list appears, with it turned on only our list. The built-in IntelliSense adds no items to the asynchronous session and its list is not shown next to ours.
- Where our source returns `DoesNotParticipateInCompletion`, the built-in IntelliSense keeps working. With the built-in IntelliSense turned off, our source still works.
- Consequence: where our source participates, it replaces the built-in IntelliSense completely. The user chose to see only our list (see Decisions), so the built-in IntelliSense never needs to be turned off.
- Not verified how SSMS suppresses the built-in IntelliSense. It is enough for now because the behavior is stable and controlled by our source.

**Question 3: yes for SQL Server authentication; Windows and Entra ID remain.**

- Our own connection from the window's data (including the password from SSMS memory and the window's `Encrypt`/`TrustServerCertificate`) opens in about 100 ms.
- `AdvancedOptions[DATABASE]` follows the database selected in the window's drop-down, so reading it on every completion is enough.
- `ScriptFactory.Instance.CurrentlyActiveWndConnectionInfo` (`SQLEditors.dll` 22.200) is reachable through reflection. `UIConnectionInfo` (`Microsoft.SqlServer.RegSvrEnum` 18.100) contains `ServerName`, `UserName`, `AuthenticationType` (SQL Server = 1), `Password` and `InMemoryPassword` (`SecureString`), and `RenewableToken` (`null` for SQL logins, a candidate for Entra ID).

## MVP

The code is in `src/` and the tests in `tests/`. Build: `dotnet build SqlPrompter.slnx -c Release` on Windows; tests: `dotnet test tests/SqlPrompter.Tests` anywhere. The manual test procedure is in the [README](../README.md).

What the MVP does:

- Keywords at the start of a statement, after a table source (`WHERE`, `JOIN` …) and in expressions; data types after `CAST(x AS` and `DECLARE @x`.
- Tables, views and table-valued functions after `FROM`, `JOIN`, `APPLY`, `UPDATE`, `INSERT INTO`, `DELETE FROM`, `MERGE`, `USING` and `TRUNCATE`/`DROP`/`ALTER TABLE`, also with a schema (`sales.|`). Without a schema they are inserted as `schema.table`.
- Columns of an alias or table (`u.|`, `dbo.Users.|`), and in expressions (`SELECT`, `WHERE`, `ON`, `GROUP BY`, `HAVING`, `ORDER BY`, `SET`) the columns of all sources of the block, aliases and common built-in functions. A column present in several sources is inserted with its alias.
- Query blocks: a subquery in an expression sees the outer query's sources, a derived table and a CTE do not; `UNION` separates blocks. Statements are separated even without semicolons.

Status: runs in SSMS 22.11; the items still to verify are in issue #7.

### Popups are owned and not topmost (verified in SSMS 22, #135)

A WPF `Popup` is hosted in its own top-level window that is topmost, so the completion list, its description panel and the parameter info stayed above other applications. `PopupWindows.Attach` makes the popup window owned by the root window of the editor (`GWLP_HWNDPARENT`) and not topmost (`SetWindowPos` with `HWND_NOTOPMOST`) each time the popup opens. ### Restoring tabs on a cold start (#140)

`ScriptFactory` lives in `SQLEditors.dll` (`Extensions\Application`), which SSMS loads only when something needs it. `SsmsConnection.ScriptFactoryType` therefore looks among the loaded assemblies first and then loads `SQLEditors` by name and from its folder. ### Quick actions on a tap of Ctrl (#125)

`CtrlTap` (created per SQL text view) listens to `PreviewKeyDown` / `PreviewKeyUp` of `view.VisualElement`; modifier-only key presses do arrive there. A tap is a Ctrl key down with no other modifier (not a repeat) followed by its key up while no other key or mouse button came between and `Keyboard.Modifiers` is `None`; in `PreviewKeyUp` of the Ctrl key `Keyboard.Modifiers` already shows `None`. `QuickActionsPopup` is a code-only WPF `Window` (no chrome, owner = the SSMS main window) opened with **`ShowDialog()`**: a modeless window opened with `Show()` never received the keyboard (SSMS routes keys through its own message loop). Its `Deactivated` handler closes it, which must not call `Close()` again while the window is already closing (`InvalidOperationException` in `Window.VerifyNotClosing`, an unhandled exception that **terminates SSMS**); the chosen action runs after the window has closed (`Closed`). The list comes from Core `QuickActionCatalog` (actions for a selection or the whole script, snippets that wrap a selection or not), the filter needs every typed word in the name or description. Verified: Ctrl tap shows the popup under the caret line at the left edge of the editor, filter `brackets` + Enter ran *Remove Square Brackets*. Facts for tests: `keybd_event` (virtual key 0x11) sends a real Ctrl tap; take screenshots without `drive.ps1` while the popup is open, because that script moves the focus and closes it.

**Chords routed to commands (#198).** Keys bound to commands (Ctrl+A, Ctrl+Space) are handled by the shell's command routing and never reach the WPF key events of the editor (see #144), so the events alone saw only Ctrl down and up and counted the release as a tap. Since VSIX 0.71.0 `InputWatcher` installs `WH_KEYBOARD` and `WH_MOUSE` hooks on the UI thread (they see every key, mouse button and wheel turn of the thread, whatever happens to it later) and counts them; `CtrlTapDetector` (Core, unit tested) compares the counter at Ctrl down and Ctrl up and gives a tap only when nothing else happened in between. If the hooks cannot be installed the counter stays 0 and the old key-event logic decides alone. Verified in SSMS 22.11 (2026-11-06, driven with `SendKeys` and `keybd_event`): a tap of Ctrl on its own (left Ctrl with its scan code) opens the popup; Ctrl+A and Ctrl+Space (also repeated, with the other key released first) do not. Also verified (popup detected by its UI Automation items): Ctrl+C, V, X, Z, E, Ctrl+Shift+Space, Ctrl+K Ctrl+C and Ctrl+wheel (repeated Ctrl+A three times) do not open it. Not verified: the build without the hooks (the old behavior), Ctrl+S.

**A second tap closes the popup (#240).** The popup (`QuickActionsPopup`, a modal window) has its own `CtrlTapDetector` fed by the window's `PreviewKeyDown` / `PreviewKeyUp` and `InputWatcher.Count`, so the filter box having the focus does not matter, and Ctrl used as a modifier (Ctrl+A, C, V) or any other key or mouse click interrupts the tap. A closing tap clears the chosen action, so nothing runs and the script is not changed; the existing `Closed` handler gives the focus back to the editor. The tap that opens the popup cannot close it: its Ctrl release is handled by the editor before the popup exists. Verified in SSMS 22.11 (2026-11-06, popup detected by the tooltip of its filter box): tap opens, Ctrl+A, Ctrl+C and Ctrl+V in the filter box keep it open, the next tap closes it, a third tap opens it again, a fourth closes it; the script text stayed the same.

**Popup on the monitor of the caret (#451).** `QuickActionsPopup.Place` used `SystemParameters.WorkArea`, the work area of the primary monitor only, so a popup for a caret on another monitor jumped to the primary one. It now takes the work area of the monitor that contains the caret point (`Screen.FromPoint`), computes in device pixels (the DIP size of the popup times the scale of the editor) with the pure `PopupPlacement.Place` (Core, unit tested: negative coordinates, monitors above and below, the right and bottom edge, a popup larger than the area), and sets the position with `SetWindowPos` in `SourceInitialized`, because `Left` and `Top` in DIPs are converted with the DPI of the monitor the window starts on. Verified in SSMS 22.11 (2026-11-13, VSIX 0.200.44) with SSMS on the secondary monitor to the left of the primary one (negative X, 1920x1080 at 100 %, the primary is 2560x1440): the popup opens under the caret line on that monitor. Not verified: different DPI scaling of the monitors, the edge cases in SSMS (covered by the unit tests only), a window spread over two monitors.

### Tabs: saving on events and the order of events at shutdown (#168)

`TabSessionService` now also writes the list when a query window is opened or saved (at once), when one is closed (700 ms later) and, as before, every 5 s for the text of unsaved queries; `TabSessionPolicy` (Core) decides whether a write is allowed (never after the shutdown was announced, an empty list at once for a user event and after two empty timer ticks otherwise, never before tabs were seen or restored). The events come from the **running document table** (`IVsRunningDocTableEvents`: `OnAfterFirstDocumentLock`, `OnAfterSave`, `OnBeforeLastDocumentUnlock` with no locks left). DTE `DocumentEvents` were not raised for a window the user closed (they did fire for the windows SSMS closes at shutdown), and neither the WPF `MainWindow.Closing` event nor `WM_CLOSE` / `SC_CLOSE` on the main window were seen when SSMS was closed with Alt+F4. **Order at shutdown (SSMS 22.11, 4 query windows, "Don't Save"):** the *Save changes?* dialog (once, for all unsaved windows), then every window is unlocked in the running document table within about 120 ms (a first unlock with locks left, then the last one), and `DTEEvents.OnBeginShutdown` follows 14 ms after the last unlock. So the closes of a user and of the shutdown cannot be told apart at the moment they happen; the write that follows a close therefore waits 700 ms and is dropped when `OnBeginShutdown` arrives, so the file keeps the tabs that were open before the burst. A cancelled shutdown (Cancel in the *Save changes?* dialog) happens before any window is closed, so nothing has to be undone. Verified in SSMS 22 with the test instance: closing a tab by hand removed it from `tabs.json` within a second; closing SSMS (Don't Save) left the file as it was before the burst; a process kill is covered by the event writes (not tried separately). Not verified: closing all tabs by hand and then SSMS right away (the empty list is written 700 ms after the last close), saved files.

### Code analysis: unexpected end of a batch (#167)

`UnexpectedEnd` (Core, called from `CodeAnalyzer`, switch `unexpectedEnd` in `analysis`, default on) looks at every batch (the text up to a line with `GO`, or the end of the script) and reports: an unterminated string, bracketed name or block comment (`Token.IsUnterminated`), every unclosed parenthesis (underlining the opening one), a CTE that no statement (`SELECT`/`INSERT`/`UPDATE`/`DELETE`/`MERGE`) follows, `BEGIN` / `BEGIN TRY` / `BEGIN CATCH` / `CASE` without `END` (`BEGIN TRAN`, `BEGIN DIALOG` and `END CONVERSATION` are not blocks), and a last token that needs something after it (`FROM`, `JOIN`, `WHERE`, `AND`, `OR`, `BY`, `SET`, `VALUES`, `INTO`, `EXEC`, `SELECT`, a comma, an operator; a final `ON` only when the last statement has a JOIN, because `SET NOCOUNT ON` is complete). Verified in SSMS 22: the example and a `WHERE` before `GO` get an orange squiggle. **SSMS's own squiggles:** a window connected to a server shows its own red squiggles for syntax errors, in places that only partly overlap ours (it marked `GO`, `SELECT` and `WHERE` of the example batch; a disconnected window shows none), so a double underline appears at the end of an incomplete statement; ours carries the reason in its tooltip. Not decided: hiding the rule for the batch under the caret (the analyzer has no caret).

### Code analysis: more rules and repairs (#208)

### The suggestion list SQL Prompter runs itself (#144)

**Finding:** in SSMS 22.11 a completion session that is started from outside the typing path (`IAsyncCompletionBroker.TriggerCompletion` from a command, with the reason `Invoke` or `Insertion`) calls our `InitializeCompletion` (it returns `ProvidesItems` with the right span), creates a session that is not dismissed, but **never calls `GetCompletionContextAsync`**, so nothing is shown; a session started by typing a letter calls it 3 ms later. The key Ctrl+Space (`Edit.CompleteWord`) reaches neither MEF command handlers (`InvokeCompletionListCommandArgs`, `CommitUniqueCompletionListItemCommandArgs`) nor `PreviewKeyDown` of the editor; the WPF key events of the editor are not given to extensions at all (a Tab pressed while our own list was open was typed into the text), the editor's *command chain* is. A command of ours bound to a key in the scope `SQL Query Editor` does receive the key every time (as Ctrl+Shift+Space for Parameter Info does).
**Solution:** `InvokedList` (one per view) is a small controller that does what the session would not: Ctrl+Space is bound (`DefaultKeyBindings`, once, only if the key is free in that scope) to the new menu command *Show Suggestions*; it asks `SqlCompletionSource.BuildForInvoke` for the items (the same preparation and `SuggestionBuilder` as the session, on the UI thread, never waiting for the database), filters them by the typed text (starts-with first, then contains), shows them in the same popup (`SqlCompletionPresenter.Present` / `Show`, which the session uses too through `Update`), moves the selection with the keys and inserts the choice with the same commit code (`SqlCommitManager.Commit`, now shared: snippets, FROM edit, INSERT/EXEC blocks, functions with parentheses, usage statistics). The keys come from `InvokedListCommands` (command handlers for Down, Up, Page Up/Down, Tab, Enter, Esc and typed characters, before the completion handler; they pass everything on while no such list is open). Where the user probably types a name of their own (soft selection) Enter keeps the text and Tab inserts. **A typed letter closes this list and the editor's own session starts as usual**, so the list only has to cover the moment between the key and the first typed character; a commit character from the settings inserts the choice first. Backspace, Delete and caret moves are noticed through the buffer and caret events and filter again or close the list when the caret leaves the typed text. The window can now be changed independently of the editor's session.
**Also found:** `SuggestionBuilder.ExpressionSuggestions` threw a `NullReferenceException` when the metadata of the database was not loaded yet (the first completion after `USE db`), which the source swallowed into an empty list; keywords, functions and snippets are offered now.
Verified in SSMS 22: Ctrl+Space after `WHERE ty` and `AS a ij` and after `WHERE ` (columns of the table, functions, keywords, scrollbar); Tab inserted the snippet `JOIN` for `ij`; Down + Enter inserted the second item; Esc closed; typing `un` after the list was open handed over to the editor's list with the matching items. Not verified: commit characters (space, dot), Backspace, mouse clicks on rows of this list, a list opened in a window without a connection.

### Column picker and "All non-aggregated columns" (#176)

**Core** (`ColumnClauses`, `ColumnPicker`, tests in `ColumnPickerTests`, 47 cases): `ColumnClauses.At` says whether the caret stands at the start of an item of a select list (after `SELECT`, `DISTINCT`, `ALL`, `TOP n` / `TOP (n)`, `PERCENT`, `WITH TIES` or a comma of the list), of a `GROUP BY` or of an `ORDER BY` (not in `WHERE`, `FROM`, `SET`, `ON`, after `UNION ALL`, inside a function call); `NonAggregatedItems` lists the items of the select list of the same block that a `GROUP BY` has to repeat, as written (aliases of both forms, `AS`, constants, `*`, subqueries, aggregates and window functions are left out; an alias without `AS` is cut unless it would cut an `END`). `CaretContext` now carries the `Text` and `Caret` it was made from. `ColumnPicker.TryBuild` gives the columns of the sources of the block grouped by source (qualified with the alias when there are several sources or the option says so) or, in `INSERT INTO t (...)`, the insertable columns that are not written yet; `Ordered(tableOrder)` is the table order or alphabetical within a source; `InsertText` uses the same layout helper as the expanded `*`. In `GROUP BY |` the normal list starts with an item **All non-aggregated columns** (also in the editor's own session, because it is an ordinary suggestion).
**List**: `InvokedList` (the own list from #144) has a second mode, the column picker: rows with a check box (`[ ]` / `[x]`), a heading per source, Space checks the selected column, Tab or Enter inserts the checked columns (the selected one when none is checked) laid out by the style, Esc closes, typing filters the columns, Select All and the check box *List in table order* (remembered in `behavior.pickerTableOrder`) are in a status bar under the list (`ListFooter` of `SqlCompletionPresenter`: the tabs *Column Picker* / *All Suggestions*, the buttons and a hint on a second line; the hint of the normal list, *Ctrl+Left: column picker*, can be closed with its x and is the option `behavior.showColumnPickerHint`). In `GROUP BY` the picker starts with the item *All non-aggregated columns*; checking it adds those items to the inserted list without repeating columns.
**Keys:** the SDK of SSMS 22 has no command arguments for Ctrl+Left / Ctrl+Right (`WordPreviousCommandArgs` and `WordNextCommandArgs` exist only in the runtime assembly), so they are bound (scope `SQL Query Editor`, only when free, like Ctrl+Space) to two hidden commands (`CommandWellOnly`, *Picker Left* and *Picker Right*). Ctrl+Left switches the own list to the picker, or, when the editor's own list is open where columns are picked (`InvokedList.CanPick`), dismisses it and opens the own list as the picker (the typed text becomes its filter); Ctrl+Right goes back to all suggestions; everywhere else the commands run `Edit.WordPrevious` / `Edit.WordNext`, so the keys keep their old meaning. Verified in SSMS 22: Ctrl+Space after `SELECT ` of a two-table query shows the list with the status bar and the hint; Ctrl+Left shows the picker with headings `p` and `c`, check boxes, Select All and the order box; Space + Down + Space + Tab inserted `p.Code` and `, p.IdProduct` laid out with commas before; `GROUP BY |` showed the item and inserted `p.IdCategory, p.Name`, the same through the picker; `INSERT INTO dbo.Products (IdCategory, |)` hid the identity and the written columns; `SELECT na` (editor's list) + Ctrl+Left switched to the picker filtered by `na`.
**Not done in this step:** the normal list does not group the columns by source with heading rows (the sort order of the list puts the columns of the sources first, as before); the picker is not offered after `ORDER BY` / `GROUP BY` by an own hint (it works, Ctrl+Left); a mouse click on a row only selects it in the normal list and toggles the check in the picker on double click; the status bar of the editor's own session list has no tabs (the tabs and the hint exist only in the own list).

## Smart suggestions: the position map (#178)

`KeywordMap` (Core, `Analysis`) reads the tokens of the current block before the word being typed (a parenthesized group counts as one token; a caret inside a function call has no position) and says which keywords can follow: `First` (the likeliest), `Then` (possible as well) and `Exclusive` (nothing else can follow: table hints, a CTE). `ContextAnalyzer` stores them in `CaretContext.PreferredKeywords` / `NextKeywords` / `OnlyExpectedKeywords`; `SuggestionBuilder.KeywordSuggestions` ranks them: in the keyword and fallback lists *first* before *then* before the rest; in an expression the keywords of a position after a complete operand (`SELECT a |`, `WHERE x = 1 |`, `CASE … END |`) rank above the columns, the others (`SELECT |`: `TOP`, `DISTINCT`) next to the aliases. Where exactly one keyword can follow (`AS` after a CTE name, `SET` after `UPDATE t`, `ON` after a joined table with its alias) the item is preselected, but only when the typed text is empty or starts that keyword (an alias being typed must not be replaced). Usage ranking still orders items within a group.

**Index DDL (#197).** `IndexDdl` (Core, `Analysis`) holds the positions of `CREATE [UNIQUE] [CLUSTERED | NONCLUSTERED] [COLUMNSTORE] INDEX`, `ALTER INDEX` and `DROP INDEX`. In these statements every position the map knows is a keyword list (kind `Fallback`, or `Keyword` when only the listed words fit), so keywords that do not fit are ranked lower, not hidden. After `ON` tables and views are offered; in the key column list and in `INCLUDE (…)` the columns of the table (`ContextKind.InsertColumns` with `IndexColumns`: all columns, without those already listed, the `INCLUDE` list also without the key columns; the column picker works there too, #200). After `WHERE` the filter predicate is an ordinary expression whose only source is the table of the index (#200). Not covered yet: index names after `ALTER INDEX` / `DROP INDEX` (needs index metadata; #200) and the other DDL statements that still fall back to generic keywords (`CREATE TABLE` column definitions and constraints, `ALTER TABLE ADD` / `ALTER COLUMN`, `CREATE STATISTICS`; #213). Verified in SSMS 22.11 (2026-11-06): after a nonclustered index key list `inc` shows `INCLUDE` first and preselected, then `DISTINCT` and snippets. Not verified in SSMS: the other positions of the table.

**Operators and values in conditions (#204).** In `WHERE`, `AND`, `OR`, `ON`, `HAVING` and `CASE WHEN`, right after a column (`WHERE col |`, `AND a.col |`, also inside parentheses and after `NOT`), `ContextAnalyzer` stores the column in `CaretContext.ConditionOperand` (parts, qualifier first; a reserved word is no column). `SuggestionBuilder` finds the column in the sources of the block and `OperatorSuggestions` (Core) offers the operators that fit its type, each in a group of its own below zero so that their order is kept: `=`, `<>`; `LIKE` and `NOT LIKE` for character types; `<`, `>`, `<=`, `>=` and `BETWEEN` for numbers and dates; `IN` and `NOT IN` (inserted as `IN ()` with the caret between the parentheses); `IS NULL` and `IS NOT NULL` last, or first for a nullable column. A bit or uniqueidentifier column gets neither `LIKE` nor `BETWEEN`. Right after a comparison operator (or `LIKE`) that follows such a column (`AfterComparison`) the values of the type of the column rank first: columns of the same type class (the others move down to the group of outer columns), script variables and parameters of a compatible type, and for a date the functions that return the current date and time. Only metadata and the script are used, never values read from the data. The type class is a plain classification of the type name (`TypeClass`). Verified in SSMS 22.11 (2026-11-06): after `WHERE Name ` and a typed `l` the list shows `NOT LIKE`, `IN`, `NOT IN`, `IS NULL`, `IS NOT NULL` above the columns. Also verified (VSIX 0.73): `IN` + Tab inserts `IN ()` with the caret inside (typing `5` gives `IN (5)`) because the plain keywords the operator items cover are not offered again; after `WHERE Created >= ` and `g` the date functions `GETDATE`, `GETUTCDATE`, `SYSDATETIME`, `SYSUTCDATETIME` come first, after the `Created` column.

**INSERT and MERGE fragments (#205).** `StatementFragments` (Core) adds whole fragments in front of the keywords, as block items (`IsBlock`, group -1): after `INSERT INTO t (a, b) |` (`CaretContext.InsertTail` / `InsertTailColumns`, found by `TryInsertTail`) `VALUES (...)` with a value by type per listed column (`SqlDefaults`, laid out by the insert layout setting) and `SELECT a, b` + `FROM `; in a MERGE (`CaretContext.Merge`: the stage is read from the keyword position, `Sources` are now also set on the keyword contexts) after `USING source |` the `ON` condition from `JoinSuggestions.Conditions` (foreign key, or columns of the same name), and after the condition or a WHEN action `WHEN MATCHED THEN UPDATE SET ...` (shared columns except the primary key, laid out by the formatting style), `WHEN NOT MATCHED THEN INSERT (...) VALUES (...)` and `WHEN NOT MATCHED BY SOURCE THEN DELETE`. Identity, computed and rowversion columns are never generated. Not done yet: the column picker for `UPDATE ... SET` (follow-up issue). Verified in SSMS 22.11 (2026-11-06): `INSERT INTO dbo.Users (Name, Email) val` + Tab on `VALUES (...)` inserts `VALUES (N'', NULL)` laid out on lines; after `USING dbo.Staging AS s` the list offers `ON t.Email = s.Email` and the other same-name conditions; after the `ON` condition `WHEN MATCHED THEN UPDATE SET ...` (comma-before style), `WHEN NOT MATCHED THEN INSERT ...` and `WHEN NOT MATCHED BY SOURCE THEN DELETE` commit as whole clauses and rank above the keywords; names keep their case when the keyword case is forced. Also verified: `SELECT ... FROM` after the INSERT list inserts `SELECT Name` / `, Email` / `FROM ` laid out by the style.

**Window functions (#215).** `Keywords.RequiresOver` / `IsRankingWithoutArguments` / `IsWindowFunction` classify the ranking and analytic functions (`ROW_NUMBER`, `RANK`, `DENSE_RANK`, `PERCENT_RANK`, `CUME_DIST`, `NTILE`, `LAG`, `LEAD`, `FIRST_VALUE`, `LAST_VALUE`) and the aggregates. **Correlated subqueries (#216).** For the first table of a subquery that has outer queries (`FROM |` after `EXISTS (SELECT ...`, `IN (SELECT ...`, `CROSS APPLY (SELECT ...`; `CaretContext.CorrelatedFrom`, set when the block has no table of its own besides the word being typed) `JoinSuggestions.Build(correlated: true)` offers the tables connected by a foreign key to a table of an outer query first (same group as after `JOIN`), inserted with the alias and without `ON`, the foreign key name on the right and the condition in the detail. **Loose matching of names (#219).** `NameMatcher` (Core) is the one matching function behind `ListOrdering.Filter` / `Matches` and the highlighting of the list SQL Prompter runs itself (invoked list, picker, the optional typing controller). A match has a kind, ranked in this order: exact, prefix, *words* (the typed text starts at word beginnings: CamelCase humps, after `_ - . space`, the end of an acronym; `BKT`, `BuKl`, `kt` for `Burza_Klient_Typ`), substring, *subsequence* (the characters in order, `bzkl`); within a kind the order of the input (group, usage, name) is kept. A cheap in-order check rejects most names first; 50,000 names are filtered in far less than the 50 ms target on a normal machine (the unit test allows 500 ms). The matched characters are highlighted (`NameMatch.Runs`). The option *Match initials and loose characters* (Tools > Options > SQL Prompter > Completion, default on) switches the loose kinds off (`BehaviorSettings.LooseMatching`). The editor's own session (typing with the built-in list controller) filters with the platform's matcher, which already does CamelCase but no arbitrary subsequence; it is unchanged. Verified in SSMS 22.11 (2026-11-06): with `SELECT * FROM bkt` and Ctrl+Space the invoked list shows `BurzaKlientTyp`, `Burza_Klient_Typ2` (words) and `BukettBook` (subsequence), the matched letters in bold. **HAVING and ORDER BY (#214).** `ColumnClauses.ShapeOf` (Core) describes the block the caret is in: the items of its select list (expression as written, alias, aggregate or not, star), the expressions of its `GROUP BY` and `DISTINCT`. `SelectListSuggestions` adds, in front of everything else (a group of its own for each item, from -100 up, so that the order of the select list is kept; the sort text of a group is `group + 100`, so the groups must not go below -100): after `HAVING`, `AND`, `OR`, `NOT` (`CaretContext.InHaving`) the aggregates of the select list as written (`COUNT(*)`, `SUM(Total)`; not the alias, which HAVING cannot use); after `ORDER BY` and after a comma in it the aliases (or the expressions) of the select list, no `*`. With a `GROUP BY` before the caret only the grouped columns and without one but with `DISTINCT` only the columns of the select list stay among the columns of the ORDER BY list (the test is the name, also when written `o.UserId`). Not done: `UNION` (the columns of the first select only), `OFFSET ... FETCH`, `OPTION` and `FOR XML/JSON` after the last item (the keyword positions of #178 stay), and the aggregates inside a parenthesized HAVING condition. Verified in SSMS 22.11 (2026-11-06): after `... GROUP BY IdUser HAVING ` and Ctrl+Space the list starts with `MAX(Qty)`, `COUNT(*)` (case kept) ahead of the columns, functions and the like; after `SELECT IdOrder AS Ord, Qty * 2 AS Dbl, Qty FROM dbo.OrderItems ORDER BY ` it starts with `Ord`, `Dbl`, `Qty` in the order of the select list; with `GROUP BY IdOrder` only `Cnt`, `IdOrder` and the grouped column remain.

**Types of same-named columns (#217).** In the data type position after `DECLARE @name ` and `CAST(name AS ` / `TRY_CAST(name AS ` (`CaretContext.TypeOfName`: the variable without `@`, or the operand before `AS`) `ColumnTypeSuggestions` offers first the exact types (length, precision, scale as the metadata holds them, e.g. `nvarchar(100)`, `decimal(18,2)`) of the tables and views' columns with the same name (case-insensitive equality, nothing fuzzier), the most common type first, the tables on the right and in the description. Only columns that are loaded count, i.e. those of tables the script already uses (the metadata loads the columns of used objects). The other types follow as before. Not done: a command or list item `@name (like Table.Column)`, user-defined and table types (the snapshot does not hold them), the column-definition completion after `DECLARE @t TABLE (` (#213). Verified in SSMS 22.11 (2026-11-06): with `SELECT * FROM dbo.Users u` above, `DECLARE @Email ` + Ctrl+Space starts with `NVARCHAR(100)` and `dbo.Users.Email` on the right, `type of dbo.Users.Email, dbo.Staging.Email` in the description.

**SET options, query hints, CATCH (#218).** `SetAndHints` (Core, `Analysis`) holds the positions of `SET` options and of `OPTION ( ... )`. At the start of a statement `SET |` offers `NOCOUNT ON`, `XACT_ABORT ON`, `TRANSACTION ISOLATION LEVEL`, `ANSI_NULLS ON`, `QUOTED_IDENTIFIER ON`, `STATISTICS IO ON`, `STATISTICS TIME ON`, `IDENTITY_INSERT`, `DATEFORMAT`, `LANGUAGE` first and more options after them; then `ON` / `OFF` after a switch, `ISOLATION LEVEL`, `LEVEL`, the isolation levels, `IO`/`TIME`/`XML`/`PROFILE`, the date formats, and after `SET IDENTITY_INSERT` the tables and then `ON` / `OFF`. `SET @x = ...` and `UPDATE ... SET` are not affected. Inside `OPTION (` and after a comma only the query hints are offered (`RECOMPILE`, `MAXDOP`, `OPTIMIZE FOR`, `HASH JOIN`, `LOOP JOIN`, `MERGE JOIN`, `FORCE ORDER`, `USE HINT`, `MAXRECURSION` and more). The `ERROR_*` functions and `XACT_STATE` are in the function list now (`Keywords.BuiltInFunctions`) and come first inside a `BEGIN CATCH ... END CATCH` block (`CatchBlock.IsInside`, token scan up to the caret). Not done: the TRY/CATCH and transaction templates (they belong to the default snippets, #227), `EXEC sp_executesql` and the system procedures with their parameters, `IDENTITY_INSERT` limited to tables that have an identity column. Verified in SSMS 22.11 (2026-11-06): `SET ` + Ctrl+Space, `SET TRANSACTION ISOLATION LEVEL ` + Ctrl+Space (the five levels), `OPTION (` + Ctrl+Space (the hints) and `err` after `SELECT ` inside `BEGIN CATCH` (the six `ERROR_*` functions first, then the snippet).

**CREATE TABLE and ALTER TABLE (#213).** `TableDdl` (Core, `Analysis`) reads the tokens of the statement and says what the caret waits for; `ContextAnalyzer` turns it into a context before any other analysis. In `CREATE TABLE t (` and `DECLARE @t TABLE (` (the item after the last comma at the first level): a new item offers `CONSTRAINT`, `PRIMARY KEY`, `UNIQUE`, `FOREIGN KEY`, `CHECK`, `INDEX`; after a column name the data types (kind `DataType`: the types of same-named columns of #217 first, then the usual sizes `nvarchar(50|100|255|MAX)`, `varchar(...)`, `char(10)`, `decimal(18,2)`, `datetime2(0|7)`, `varbinary(MAX)` (`CaretContext.DataTypeSizes`), then all types); after the type the options that are not there yet (`NOT NULL`, `NULL`, `IDENTITY(1,1)`, `DEFAULT`, `PRIMARY KEY`, `UNIQUE`, `REFERENCES`, `CHECK`, `COLLATE`, `CONSTRAINT`), `KEY` after `PRIMARY` / `FOREIGN`, `CLUSTERED` / `NONCLUSTERED` after `PRIMARY KEY` / `UNIQUE`, the tables after `REFERENCES`, `ON DELETE` / `ON UPDATE` after the referenced table or its columns, then `CASCADE`, `SET NULL`, `SET DEFAULT`, `NO ACTION`; table constraints after `CONSTRAINT name` (`PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `CHECK`, `DEFAULT`) and their continuation; a constraint name is yours to type (kind `Name`, an empty list). After `ALTER TABLE t`: `ADD`, `ALTER COLUMN`, `DROP COLUMN`, `DROP CONSTRAINT` first, then `ADD CONSTRAINT`, `CHECK` / `NOCHECK CONSTRAINT`, `ENABLE` / `DISABLE TRIGGER`, `WITH CHECK` / `WITH NOCHECK`; the columns of `t` (kind `InsertColumns` with `IndexColumns`, all of them) after `ALTER COLUMN` and `DROP COLUMN` (also after a comma); after `ALTER COLUMN c` and `ADD c` the data types, then `NULL`, `NOT NULL`, `COLLATE` (ALTER) or the column options (ADD). Not done: naming constraints by convention (`PK_t`, `FK_t_ref`), the key columns of the referenced table inside `REFERENCES t (|`, the names of existing constraints after `DROP CONSTRAINT` (the snapshot holds no constraints), `SWITCH` / `REBUILD`. Verified in SSMS 22.11 (2026-11-06): after `CREATE TABLE dbo.NewT (Phone ` the sized types `NVARCHAR(50)`, `(100)`, `(255)`, `(MAX)` ... come first; after `Phone nvarchar(20) ` the options; `ALTER TABLE dbo.Users ` offers `ADD`, `ALTER COLUMN`, `DROP COLUMN`, `DROP CONSTRAINT` ...; `... DROP COLUMN ` lists the five columns of `dbo.Users`; `... REFERENCES dbo.Users (IdUser) ON DELETE ` offers `CASCADE`, `NO ACTION`, `SET DEFAULT`, `SET NULL`.

Cases are in `KeywordMapTests`, `KeywordMapMoreTests`, `IndexDdlTests`, `OperatorSuggestionTests`, `StatementFragmentTests`, `WindowFunctionTests`, `CorrelatedSubqueryTests`, `NameMatcherTests`, `HavingOrderByTests`, `ColumnTypeTests`, `SetAndHintsTests` and `TableDdlTests`. A position unknown to the map keeps the old behavior (all keywords, with those the analyzer preferred before first). Not covered yet: the clauses of `CREATE TABLE` / `ALTER TABLE`, `EXEC` parameter names (offered elsewhere), `FETCH` of cursors, `FOR` after `DECLARE … CURSOR`. Verified only by unit tests (and four positions in SSMS 22) until the user tests the VSIX.
**ALTER of a module (#203).** After `ALTER PROCEDURE | PROC | FUNCTION | VIEW | TRIGGER` (also `CREATE OR ALTER` and `DROP`) the context is `ObjectName` with `Module` / `ModuleAction` / `ModuleHeaderStart` set and the list holds only modules of that kind (no snippets, no keywords): procedures and (user) views and functions from the snapshot, triggers from the new `IDatabaseMetadata.Triggers` (`DbTrigger`: schema, name, parent as `schema.table`; database DDL triggers have none), read by the last result set of the objects query (`sys.triggers`, checked against the Docker test instance). `ALTER` and `CREATE OR ALTER` items carry a `ModuleScript` (`Suggestion.Tag`). In the SSMS layer the commit (`SqlCommitManager`) inserts the name at once, then `ModuleScriptInserter` loads the definition in the background (`DefinitionPreview.Request`, never waiting on the UI thread) and replaces the text from the start of the statement (a tracking point) to the end of the name with `DefinitionScript.ToAlter` (the first `CREATE`, with its `OR ALTER`, becomes `ALTER`; comments, case and the rest are kept; `SET ANSI_NULLS` lines are not added). The caret goes to the line after the first `AS` of the header (`DefinitionScript.BodyStart`). If the text was edited meanwhile, or there is no script (encrypted, no `VIEW DEFINITION`), the name stays and the status bar says why. `DROP` items insert the name only. Verified in SSMS 22.11 (2026-11-06, test database with a table, view, procedure, DML trigger and function): `ALTER TRIGGER tr` + Tab, `ALTER PROCEDURE get` + Tab, `ALTER VIEW act` + Tab and `CREATE OR ALTER FUNCTION fnU` + Tab replace the typed text with the whole current definition (`ALTER`, resp. `CREATE OR ALTER`), the status bar says "inserted the definition of ..."; `DROP VIEW act` + Tab inserts `dbo.ActiveUsers`. Also verified: for `ALTER PROCEDURE` the caret lands at the start of the line after the `AS` of the header; an encrypted procedure keeps just the name. Not verified: a module without permission, a text edited while loading. Not covered: `ALTER TABLE |`, `ALTER SEQUENCE |`, `DROP TABLE |` (name-only lists of one kind) and database DDL triggers' scripts (they are not found by `DefinitionLoader`, so only the name is inserted).

Cases are in `KeywordMapTests`, `KeywordMapMoreTests`, `IndexDdlTests` and `AlterModuleTests`. A position unknown to the map keeps the old behavior (all keywords, with those the analyzer preferred before first). Not covered yet: the clauses of `CREATE TABLE` / `ALTER TABLE`, `EXEC` parameter names (offered elsewhere), `FETCH` of cursors, `FOR` after `DECLARE … CURSOR`. Verified only by unit tests (and four positions in SSMS 22) until the user tests the VSIX.

**Snippets** are offered in every position (not after a qualifier and not in a name that is being invented): those whose prefix starts with the typed text in group 1 (next to the aliases), all the others (those that contain it and, before a character is typed, all) in the last group (`SuggestionBuilder.SnippetsLastGroup`, 50). Usage ranking takes precedence: a snippet that was chosen before is sorted as if it were in group 1 and, within the group, by the number of uses (`Suggestion.RankedSortText`).

## Compatibility gate (#186)

`SsmsCompatibility` (Ssms) probes at start, on the UI thread and before the tabs are restored, everything undocumented that SQL Prompter relies on; the list of requirements, their features and the report are in Core (`CompatibilityRequirements`, `CompatibilityReport`, tests in `CompatibilityTests`). A requirement that is not found (a probe returns text or throws) switches off only the features that need it: `ActiveConnection` (the connection of the window: metadata, history, tab colors), `OpenWindow`, `RestoreTabs`, `ResultsGrid`, `ExecuteHook` (metadata refresh after DDL, execution warnings, history) and `WordKeys` (Ctrl+Left/Right pass-through). The log gets the build and every missing requirement, and the user is told once per outcome (the SSMS build and what is missing; remembered in `%LOCALAPPDATA%\SqlPrompter\compatibility.txt`) by a message box. Requirements (12): `ScriptFactory` type, `Instance`, `CurrentlyActiveWndConnectionInfo`, `UIConnectionInfo` type, its properties `ServerName`/`UserName`/`AuthenticationType`/`AdvancedOptions`, its parameterless constructor, `CreateNewBlankScript(…, UIConnectionInfo, …)` and the DTE commands `Edit.CopywithHeaders`, `Query.Execute`, `Query.Disconnect`, `Edit.WordPrevious`, `Edit.WordNext`. A new undocumented dependency is added to `CompatibilityRequirements` and to the probe.

**Tested SSMS build: 22.11.12328.437** (all 12 requirements found, verified 2026-11-06). The environment variable `SQLPROMPTER_SIMULATE_MISSING` (ids separated by commas) makes the probe report requirements as missing, to try the gate: with `Command.Edit.CopywithHeaders,ScriptFactory.CreateNewBlankScript` the log said "10 of 12 … found" and switched off opening windows, restoring tabs and the grid actions; a message box with the build and the switched-off features appeared once. The smoke script `.claude/skills/drive-ssms/smoke.ps1` (run after an SSMS update) checks the compatibility line of the log and makes screenshots of four completion scenarios (`drive.ps1` cannot read the items of our own list through UI Automation any more, so they are judged by looking). Not covered by the gate: the tab color view model members (`TabAccentBrush`, `IsTabGroupColorized`, `IsActive`) that are found on a tab object at runtime.

## The list for typing through our own controller (#187, step 1)

The option *Run the list myself while typing (experimental)* (`behavior.ownTypingList`, default off; Settings → Completion) makes the list that opens while typing the same list as Ctrl+Space (`InvokedList`) instead of the editor's completion session. How it works:

- `InvokedListCommands` is now a chained handler of `TypeCharCommandArgs`: it first offers the character to an open list (`OnTypedChar`: a commit character inserts the selected item), then lets the editor insert it (`nextCommandHandler`), and then, if no list is open and the character can start a list (`SqlCompletionSource.StartsList`, the same characters as the session's `IsTrigger`), calls `InvokedList.OpenForTyping`.
- `SqlCompletionSource.BuildForTypingAsync` prepares on the UI thread with the same rules as the session (`Initialize(…, out Prepared)` no longer shares the `pending` field with the session) and builds the items on a background thread (`Task.Run`, sorted by `ListOrdering`); the result is dropped when the user has typed more in the meantime (the newest request wins).
- With the option on, the editor's session still takes part for a typed character (so that the built-in list does not show) but offers nothing (`ProvidesItems` with an empty span, as while a snippet field is typed).
- A list opened by typing (`typingMode`) stays open while letters are typed: the typed text is part of its span, the text buffer change filters again (`ListOrdering.Filter`), and Backspace / caret moves close it when the caret leaves the span. Esc, Up/Down, Tab and Enter work as in the Ctrl+Space list; the status bar with the column picker is the same.

Verified in SSMS 22.11 (VSIX 0.60.0): after `dbo.` the list opens; `ca` filters it to Categories and Tab inserts `Categories AS c`; `SELECT na` shows `Name` with the matching part in bold and the matching snippets at the end; Backspace shows all items again; Down + Enter insert the second item. Not verified yet: IME, very fast typing, snippet fields, comma/space triggers, the picker after typing (checklist in #187).

**Built-in snippets (#227).** `BuiltInSnippets` (Core) holds about 35 snippets of our own (queries, data changes, structure, control flow, information) with ids derived from the prefix, fields for the values to fill in and `$CURSOR$` for the end. `BuiltInInstaller` writes each one to the snippet folder once: the ids that were installed are listed in the marker file `.builtin-snippets` (not a .json file, so the loader ignores it), so an edited or deleted snippet is never written again, and a snippet of the user with the same prefix is skipped. `SnippetService.Reload` runs it before loading when the setting `Snippets.InstallBuiltIn` is on (default). `Restore(id)` writes the original text back; there is no command for it yet. Unit tests check that every body expands to balanced T-SQL without leftover fields and the install rules. Verified in SSMS 22 (2026-11-06): on the first start with the new build 29 snippets were written to the snippet folder (the others had prefixes of existing snippets of the user), the log says so, and `top100` + Tab expands to `SELECT TOP (100) *` / `FROM dbo.Table` with the field selected.

**UPDATE SET column picker (#232).** `ColumnClause.UpdateSet` (`ColumnClauses.IsUpdateSet`: the SET belongs to an UPDATE of the same statement, so `SET NOCOUNT` and `SET @x` are not affected) makes `ColumnPicker` list the assignable columns of the first source (identity, computed and rowversion columns left out, columns assigned already hidden by `ColumnClauses.ExistingAssignments`). A chosen column is inserted as `Name = value` with the value by type from `SqlDefaults`, several columns laid out by the formatting style like an expanded star. Covered by unit tests in Core. Verified in SSMS 22 (2026-11-06): `UPDATE dbo.Users SET ` + Ctrl+Space + Ctrl+Left lists the assignable columns, checking two and Tab inserts `Active = 0` and `, Created = '1900-01-01'` laid out by the style; after `SET Active = 0, ` the assigned column is gone from the picker.

**Script outline (#224).** `ScriptOutline.Build` (Core) turns a script into `OutlineItem`s (kind, name, line, offset, depth) from the lexer and `StatementSplitter`: batches (GO), statements (first line, shortened), variables of DECLARE, temporary tables (`CREATE TABLE #t`, `SELECT ... INTO #t` as created, `DROP TABLE #t` as dropped), CTE names and the header of a procedure, function, view or trigger; unfinished code gives a shorter outline and never fails. The command Script Outline (menu SQL Prompter, `0x012C`) opens the quick actions popup with these entries (`QuickActionsPopup.ShowOutline`); typing filters, Enter moves the caret and centers the line. Verified in SSMS 22 (2026-11-06): a script with two batches, a variable, a temp table and a CTE is listed in order, and typing `CTE` + Enter puts the caret on line 4. Added later: the popup preselects the item at the caret, blocks (IF, ELSE, WHILE, BEGIN TRY, BEGIN CATCH; kind `Block`) and the parameters of a procedure or function (kind `Parameter`) are listed, and the jump commands (`ScriptOutline.JumpTarget`, `ScriptJump`) move the caret; after review they are not menu commands but two entries of the quick actions popup (Go To Next Batch, Go To Previous Batch), and jumping to a statement stays in the outline. A DTE key name for Page Down is `PgDn`, not `Page Down` (that gave E_INVALIDARG). Verified in SSMS 22 (2026-11-13): all four keys move the caret as expected, and the popup opened with the item of the caret line selected and listed the blocks and the parameter. Not done: a tool window that stays open and refreshes after an idle time.

**Quick open (#223).** `ObjectFinder.Search` (Core) lists the non-system objects of the loaded metadata (tables, views, functions, synonyms, procedures, triggers) matching the typed text with `NameMatcher` (loose: initials, words, characters in order; a dot in the text matches the full `schema.name`), ordered by match kind, name length and name, at most 200. The command Quick Open Object (menu SQL Prompter, `0x012D`) opens the quick actions popup with a search function instead of a fixed list (`QuickActionsPopup.ShowObjects`): Enter opens the script in a new window (`GoToDefinitionHandler.OpenObject`, the loader of F12), Shift+Enter inserts `schema.name` at the caret. It uses only the cached metadata, so it opens at once and says so in the status bar when it is not loaded. Verified in SSMS 22 (2026-11-06): `ord` lists `Orders` and `OrderItems`; Shift+Enter inserted `dbo.Orders`; `orderi` + Enter opened the `CREATE TABLE` script of `dbo.OrderItems`. Not done: a default shortcut, other databases of the server, recently used objects, Ctrl+Enter in Object Explorer, type icons.

**Find in database code (#212).** `CodeSearch` (Core) compiles the text with the options (case, whole word, regular expression; a bad expression gives null) and finds the matching lines of a script, numbered like the script that F12 opens (`DefinitionScript.ToCreateOrAlter` keeps the lines). `CodeSearchLoader` (Metadata) reads `sys.sql_modules` of procedures, functions, views and triggers that are not Microsoft-shipped on a connection of its own, counts modules without text (encrypted) and returns the hits. The command Find In Database Code (menu SQL Prompter, `0x012E`) searches for the selection or the word at the caret as a whole word, on a background task with a 60 s limit, reports the counts in the status bar and lists the lines in the popup (`QuickActionsPopup.ShowItems`); Enter opens the object in a new window and puts the caret on the line (`GoToDefinitionHandler.OpenObject` with a line). Verified in SSMS 22 (2026-11-06): with the caret in `OrderItems`, the search found the one line of `dbo.ListOrders` that uses it, and Enter opened the procedure with the caret on line 5. Not done: a window with the options (case, regular expression, other databases, object types), a cancel button, a preview pane and the command Where Is This Used (`sys.sql_expression_dependencies`).

**Dependencies (#222).** `DependencyLoader` (Metadata) reads `sys.sql_expression_dependencies` for one object on a connection of its own: what the object uses (`referencing_id`, with the type from `sys.objects` when the object is local) and what uses it (`referenced_id`). The command Show Dependencies (menu SQL Prompter, `0x012F`) takes the object at the caret (`ObjectReferenceFinder`), reads in the background (30 s limit) and lists "Uses: ..." and "Used by: ..." with the kind in the popup; Enter opens the script of an object of the same database (an object of another database says so in the status bar). Verified in SSMS 22 (2026-11-06): for `dbo.OrderItems` the list showed the procedure `dbo.ListOrders` that uses it. Not done: Ctrl+F12 (select the object in Object Explorer, which needs research of the SSMS API), the Dependencies tab of the definition panel, a tree with type icons, objects of linked servers, the context menu entry.

**Descriptions from the database (#206).** `DescriptionLoader` (Metadata) reads `MS_Description` of one object and its columns from `sys.extended_properties` (one query by `OBJECT_ID`, `minor_id = 0` is the object) on a connection of its own; `DescriptionText.Format` (Core) makes the text: the object description (shortened to 600 characters), then one line per described column (name: text, 120 characters, 12 columns, then a count). Verified in SSMS 22 (2026-11-06): `dbo.Orders` with a table and a column description shows `Customer orders, one row per order` and `IdOrder: Primary key of the order` under the item description; `dbo.OrderItems` without any shows nothing extra. **Reopen closed query tab (#226).** `ClosedTabs` (Core) follows the list of open tabs that `TabSessionService.Save` builds (key = document name, value = `SavedTab`): a key that was in the previous list and is missing now is a closed tab, kept with its last known state (newest first, at most 20, an unsaved tab without text is not kept). The command Reopen Closed Query Tab (menu SQL Prompter, `0x0130`) pops the last one and opens it with `OpenTab`, the code that restores tabs at start (a saved file is opened again, a new window gets its text and, as the session does, a comment with the connection, because a password is never stored). The log line `Tabs open (described)` shows the tabs that the session knows. A finding: a window created a moment ago fails once in `Describe` (`TextDocument.StartPoint` E_FAIL) and is described on the next tick, so a tab closed within about 5 s of being created is not remembered. Verified in SSMS 22 (2026-11-06): closing a window with `SELECT 'third'` (Don't Save) and running the command opened a new window with that text and the connection comment. The list lives only in memory (not kept over a restart of SSMS). Not done: a default shortcut, the list of closed tabs in the quick actions and the history window, renaming a tab, the setting for number and time.
**Shared snippet folders (#228).** `SnippetSettings.SharedFolders` (semicolon-separated, in the user's settings only) lists more folders in the same JSON format. `SnippetService.Reload` loads each one and `SnippetMerge.Merge` (Core) combines them with the personal folder: shared snippets get `Snippet.IsShared` (not written to the file), a personal snippet wins over a shared one with the same prefix, and an earlier shared folder wins over a later one. Covered by unit tests in Core. Verified in SSMS 22 (2026-11-06) with a folder set in the settings file: the log said `loaded 157 (1 shared folders)`, `zzshared` + Tab expanded the shared snippet, and a second file dropped into the folder was loaded by the watcher a few seconds later (158). Not done: several folders in a folder picker (the setting is a text field), and read-only handling of a shared folder that is not writable (the manager never writes into it).
**Confirmation of changes and open transactions (#209).** `ChangeWarnings` (Core) lists the statements of a script that change data or schema (`UPDATE`, `DELETE`, `TRUNCATE`, `DROP`, `ALTER`, `CREATE OR ALTER`, `MERGE`, `EXEC sp_rename`; temporary tables and table variables are left out) and finds a `BEGIN TRAN` without `COMMIT`/`ROLLBACK` in the same batch (`OpenTransactionLine`; batches that store a procedure, function or trigger are skipped). `ExecutionHooks.ConfirmExecution` (the existing `Query.Execute` hook; `cancelDefault = true` cancels the run) adds them to the dialog of the execution warnings: the changes when the coloring rule that matches the window's server and database has `AskBeforeChanges` (a check box column of the rules grid in the settings, deliberately per rule and not per environment, so one database of a server can be protected), the open transaction when `WarnOpenTransaction` is on (default). Verified in SSMS 22 (2026-11-06) with a temporary rule (`askBeforeChanges`) for the Docker test database in the settings file (restored afterwards): running `UPDATE dbo.Users SET Name = Name WHERE 1 = 0` followed by `BEGIN TRAN` showed the dialog "Environment Production (server localhost,1433, database SqlPrompterTest_Verify) asks before changes" with the UPDATE and the open transaction, and No cancelled the run (`Execution cancelled after a warning.` in the log). **Pinned history runs (#225).** `HistoryEntry.Pinned` is stored as an additive line `{"id": ..., "pinned": "1"|"0"}` in the history file (and in the entry line when the file is rewritten), so older files load and older versions ignore it. `HistoryStore.SetPinned` writes it, `Prune` never removes a pinned run and `Filter` lists pinned runs first, then newest first. **Tooltip over names (#220).** `HoverInfo.At` (Core) finds the name under a position (the dotted name that ends with it) and describes it from the loaded metadata and `ContextAnalyzer.SourcesAt`: a table or view with the column count and primary key, a synonym with its target, an alias with its table, `alias.column` or an unambiguous bare column with type, nullability, identity/computed/rowversion and key, a function or procedure with its parameters, a variable with its `DECLARE` type; keywords, numbers, temporary tables and unknown names give nothing. `HoverQuickInfoProvider` (`IAsyncQuickInfoSourceProvider` for the SQL content type, setting `ShowHover`, default on) switches to the UI thread only to read the cache, never waits for the database, and returns a stacked `ContainerElement`. **History of query tabs and their versions (#302).** The history knows tabs, not only runs. `TabHistoryStore` (Core, file `%APPDATA%\SqlPrompter\tabhistory.jsonl`, one JSON object per line: `tab`, `ver`, `meta`, `close`, `open`) keeps per tab the document, name, server and database, the time it was opened and closed and the versions of its text. `TabHistoryService` (SSMS) checks the open query tabs every 5 s (setting): the work on the UI thread is reading the text of each tab; a text becomes a version once it has stayed unchanged for one check and at least the check interval after the last version (`Track`); empty tabs are not stored; a version is also stored at once when a tab is saved or run, a tab opens and when SSMS shuts down (`Flush`). A closed tab keeps the text the last check saw (`Close`). Tabs of an ended session are closed at their last change when the file is read, and a restored tab with the same text, server and database takes the old entry over, so a restart does not duplicate it. Closed tabs older than *Keep history for* days are removed. The history window has the views *Everything*, *Runs* (the executed queries), *Pinned*, *Favourites*, *Open tabs* and *Closed tabs* (tab entries; a row shows the last change, the closing time and the number of versions); the right-click menu has *Versions* (newest first; choosing one opens that text in a new tab, hovering shows it in the preview). **Finding: the document of a closed query window stays (#302, #303).** SSMS 22 keeps the document of a closed unsaved query window in `dte.Documents` and in the running document table, with `Document.Windows.Count == 0` (verified in the log: `SQLQuery5.sql(w0)` after the window was closed with *Don't Save*), and the table events do not tell when the window is really gone (`OnBeforeLastDocumentUnlock` fires while the window is open and before the *save changes?* answer, and the cookie stays valid). ### Code analysis: light bulb, more repairs, rules with metadata (#208, follow-up)

**Light bulb (verified mechanism).** The standard `ISuggestedActionsSourceProvider` (`CodeFixLightBulb.cs`, content type SQL) works in the SSMS 22 SQL editor: Ctrl+. at the caret (and the bulb in the margin) lists *Fix: <message>* for the issues with a repair under the caret and *Fix all code analysis issues in the script*; an action is one buffer edit, so one Undo reverts it (verified: Fix all on five kinds of issues, one Ctrl+Z restored the script). It works from the text of the script and the metadata of the database the script uses (`MetadataService.MetadataForScript`: the last `USE` line, else the window's database); the SSMS layer reads the connection on the UI thread (`MetadataOf` switches to it), nothing waits for the database. The squiggles, the command and the quick action *Fix Code Analysis Issues* use the same metadata.
**Repairs added** (`CodeAnalyzerFixes.cs`, only for the plain shapes they understand, otherwise the issue has the message only): `TOP` without `ORDER BY` gets `ORDER BY` the primary key of its single table (needs the loaded metadata; not with DISTINCT, GROUP BY, JOIN, several tables or no key); `col NOT IN (SELECT c FROM t [WHERE ...])` becomes `NOT EXISTS (SELECT 1 FROM t WHERE ... AND t.c = col)` only for a *qualified* outer column (an unqualified one would mean the column of the subquery itself, its own scope wins) and a subquery without JOIN, GROUP BY, ORDER BY, TOP, UNION or a column list; `FROM a, b WHERE a.x = b.x AND ...` becomes `FROM a JOIN b ON a.x = b.x WHERE ...` (plain tables with aliases, top-level `AND` conditions of the form `q1.c = q2.c` are the ON conditions, the rest stays in WHERE, a table without such a condition gets `CROSS JOIN`; not with OR, a subquery, an existing JOIN or hints).
**Rules with metadata** (`CodeAnalyzerMetadataRules.cs`, switches *Ambiguous column* and *Implicit conversion*, default on, silent while the columns of a table of the query are not loaded or a source is not a plain table): an unqualified column that two tables of the query have (message names the candidates, no repair, names of select-list aliases are skipped); a column compared with a literal of another type family: `varchar` with `N'...'` (repair: drop the `N` when the text is ASCII), `varchar` / `nvarchar` with a number, a number column with a string (repair: write the number when it is all digits).
Verified in SSMS 22 (0.156.0, light theme): the squiggles of an ambiguous column and of TOP; Ctrl+. offers the repair and *Fix all*; Fix all turned `FROM Countries c, Cities k WHERE ...` into a JOIN, `IdCountry = '2'` into `IdCountry = 2`, `TOP 5` got `ORDER BY [IdCity]`, `ci.IdCity NOT IN (...)` became `NOT EXISTS (...)` and `varchar` got `(100)` in one edit. Not verified in SSMS: the dark theme, `N'x'` repair and the other implicit conversion messages (unit tests), views and synonyms as sources.

### The list opens after a space that follows WHERE, GROUP BY, HAVING and similar keywords (#382)

The decision stays one function in Core, next to `CommaTrigger`: `KeywordSpaceTrigger.ShouldOpen(text, caret, context)`. It is true when the context analyzer says an expression is expected at the caret (`ContextKind.Expression`, no typed prefix, no qualifier), the character before the caret is the typed space, and the last token before it is a reserved keyword that expects something (`WHERE`, `AND`, `OR`, `ON`, `HAVING`, `BY`, `SET`, `SELECT`, `WHEN`, `THEN`, `ELSE`, `CASE`, `NOT`, ...; not `NULL`, `END`, `ASC`, `DESC`, ...) or an operator that continues an expression (`=`, `<`, `>`, `+`, `-`, `/`; not `*`, so `SELECT * |` stays closed). There is no list of keywords for contexts: a new context that the analyzer reports as an expression works without another rule. Nothing opens after a complete name or alias (`FROM dbo.Orders |`), after a literal (`x = 1 |`), after `IS NULL`, in a string or a comment. `SqlCompletionSource.InitializeCompletion` asks it for a typed space (after `ObjectName` contexts and the comma rule of #141), and the list of our own (`InvokedList.OpenForTyping`) goes through the same source. Verified in SSMS 22 (0.161.0, light theme): a space after `WHERE` opens the columns of the table of the query (`IdCountry`, `IdCity`, `Name`, `Population`, after the first load of the metadata), after `GROUP BY` it opens with *All non-aggregated columns* and the column picker, after `FROM dbo.Cities c ` nothing opens. Not verified in SSMS: `HAVING`, `ORDER BY`, `ON`, `SET`, `SELECT`, `WHEN` (unit tests: 13 positive and 11 negative cases), the dark theme. Note: after `WHERE ` the snippets still come among the items; they are not changed by this issue.

### The list opens after a snippet is inserted (#353)

After a snippet was expanded (`SnippetInserter.Insert`, which every route goes through: the completion commit by Space, Tab and Enter, the own list, the quick action and the *Insert Snippet* command) the context at the caret is analyzed with the same `ContextAnalyzer` the completion source uses; `ListAfterInsertion.ShouldOpen` (Core) is true for the contexts that have items of their own (`ObjectName`: the tables after `JOIN` and `FROM`, `Expression`: the columns, `InsertColumns`) and when no prefix is typed, and false for keywords only, a name of the user's own and no context. The list of our own (`InvokedList.Open`, the code of Ctrl+Space) is then opened once the editor has finished the commit (`StartOnIdle`), so it does not take part in it. Not for a snippet with fields (the first field is selected and the snippet session owns Tab and Enter; the field navigation of #196 does not open lists yet), not when the automatic list is switched off, and not for a snippet with `"noSuggestions": true` in its file (an optional member, left out when false; older files load). Esc closes the list and the next Tab goes to the editor as before. Verified in SSMS 22 (0.162.0, light theme): `ij` + Tab after `FROM dbo.Cities c` inserted `JOIN ` and the list of tables opened at once (with the joins by foreign key first), the same for `lj` (`LEFT JOIN `) and for `ssf` (the tables with the definition panel). Not verified: the quick action and the *Insert Snippet* command, a snippet that ends in a context without items (unit tests), the dark theme. Not done: opening the list when the field navigation of a snippet moves to a field.

**SQL Prompt style import: align comparison operators (#305, step 3).** `FormatStyle.AlignComparisons` (`operators.comparison.align`, window: Conditions group, default off): in the conditions of WHERE, HAVING and ON that are on separate lines the comparison operators (`= <> != < > <= >= !< !>`) start in one column; the left side is padded to the longest one plus one space (`SqlFormatter.AlignedComparisons`). ### Changed objects are reloaded for the analysis and the definition window (#423)

Causes found: (1) the fingerprint check of `sys.objects` ran only from completion, so a change made in another tab, on another connection or outside SSMS was noticed only after the user had completed something in that window; hover, parameter info and the code analysis never started it. (2) The code analysis ran only after a text or settings change, so a snapshot replaced by the refresh (DDL in the same tab) did not trigger it and the old result stayed. (3) The definition shown in hover and the list preview came from a 2 minute cache that no refresh dropped. Parameters and defaults of procedures live in the snapshot (`DbProcedure`), so they are current as soon as the snapshot is. Fixes: `DatabaseMetadataCache.SnapshotReplaced` (raised after a load and after a reload caused by a change, not after columns) re-runs the analysis of every open editor and invalidates `DefinitionPreview`; `MetadataService.CacheForActiveWindow` (window activation, analysis, hover, completion) checks the fingerprint at most every 30 s; *Refresh Metadata* (`RefreshNow`) drops snapshots and definitions, starts the load at once and shows "refreshing metadata..." / "metadata refreshed." in the status bar. Verified in SSMS 22.11 (VSIX 0.199.0) against the Docker instance: `ALTER PROCEDURE` run outside SSMS was picked up by the next activity within the interval (log: "refreshed after objects changed"); Refresh Metadata reloaded the snapshot at once. Not verified: the visible effect on hover text and the squiggles. SQL Prompter has no analysis rule that produces "expects parameter ... which was not supplied"; that text is a SQL Server error.

**Follow-up (#423, VSIX 0.200.0): the red squiggle and the "expects parameter ... which was not supplied" text come from SSMS's own IntelliSense, which has its own metadata cache.** Only the DTE command `Edit.RefreshLocalCache` (Ctrl+Shift+R) reloads it. *Refresh Metadata* and every reload caused by a detected change (`DatabaseMetadataCache.ObjectsChanged`) now execute it (log: "SSMS IntelliSense cache refreshed."). Verified in SSMS 22.11: with `EXEC dbo.p_Reload @A = 0` against a procedure whose `@B` had no default the editor showed the squiggle and 1 error; after `ALTER PROCEDURE ... @B date = NULL` run outside SSMS and *Refresh Metadata* the status bar said "No issues found".

**Tab color: the whole tab, and the setting (#438, research and implementation, verified in SSMS 22.11, VSIX 0.200.32, light theme; dark theme checked on the tab strip).** *What the shell does* (decompiled `Microsoft.VisualStudio.Platform.WindowManagement.dll`, `DocumentTabItemStyle.xaml`): the style of the tab only draws the 3 px `AccentRect` (visible when the option *Tab colorization method* is not None **and** `DocumentView.IsTabGroupColorized`; the brush is `TabAccentBrush`) and the border under the selected tab; neither fills the tab. `DocumentView.UpdateTabColor` (async) sets `IsTabGroupColorized` and `TabAccentBrush` from the file color service whenever `Hierarchy`, `ItemId`, the title or the service's `ColorsChanged` change (see #439). *The Connect dialog color:* `UIConnectionInfo` has `UseCustomConnectionColor` and `CustomConnectionColorArgb` (`RegisteredServers.dll`, read by `UIConnectionInfoUtil.GetCustomConnectionColor`); `SQLEditors.dll` uses it for the status bar of the query window (`QEStatusBarManager.TransitionIntoOnlineMode`) and offers it through `ISqlEditorService.GetCustomConnectionColorForSpecificQueryEditor`. **What draws the whole-tab fill for it was not found:** no assembly of the installation other than `SQLEditors.dll` and `SqlWorkbench.Interfaces.dll` mentions the service method, the tab style has no such trigger, and setting the two properties on the clone of the connection info that `SsmsConnection.OpenNewWindow` passes to `ScriptFactory.CreateNewBlankScript` changed neither the tab nor the status bar of the new window (the dialog most likely applies the color through its own path). The tab and its `DocumentView` of a window with the color were not compared because the Connect dialog could not be driven reliably. *Implementation instead:* `DocumentTabItem` is a WPF `TabItem` whose template binds the border to its own `Background`, and a **local value** on it wins over the triggers of the shell style (selected, hovered, active), so `TabColoring.ApplyFill` sets `Background` to the environment color and `Foreground` to black or white by the luminance of the color (the same rule as the status bar), also for tabs that are not in front; the accent mechanism (`TabAccentBrush` + `IsTabGroupColorized`, which also colors the frame under the selected tab) stays in both styles. The setting `fillTab` (`ColorSettings.FillWholeTab`, default **true**, also for settings files without it) is the combo *Tab color style: Whole tab / Accent bar* on the Coloring page; a change reaches the open tabs at once (`SettingsService.Changed` runs `TabColoring.Update`, which clears the local values for the accent bar). Verified: all three tabs filled with the color of their rule with readable text (light and dark), the accent bar look is the previous one, and switching the combo with *Apply* changed the open tabs without a restart. The colors of the Connect dialog (16 palette colors) are not involved: our colors are any RGB. Not verified: whether the shell resets the local values on rename, save, theme change or reconnect (the one-second timer sets them again; the immediate reaction is #439), the tab menu *Tab Color* swatch.

**The tab color no longer flashes when a query runs (#439, verified in SSMS 22.11, VSIX 0.200.33).** Cause (decompiled `DocumentView`): the shell calls `UpdateTabColor` whenever the title of the view changes (the caption becomes `... Executing...` when a query starts and changes back when it ends), and that asynchronous method sets `IsTabGroupColorized` and `TabAccentBrush` from the file color service (the shell's own group color) again; the one-second timer of `TabColoring` put our color back only at the next tick. Measured with a pixel sampler on the accent rect of the active tab (`WAITFOR DELAY '00:00:04'`, F5): before, the pixel showed the shell color for about 160 ms at the start and again for about 180 ms at the end of the run; after, it stayed at our color for the whole run. The fix: for every tab we color, `TabColoring.Hook` adds a `DependencyPropertyDescriptor` value-changed handler to `TabAccentBrushProperty` and `IsTabGroupColorizedProperty` of the `DocumentView` (public static fields of `WMView`, found by reflection); the handler (`Reassert`) sets our color back **in the same call**, before the tab is drawn, when `TabColorGuard.MustReassert` (Core, tested) says the state is not ours; a flag (`settingOurselves`) keeps the handler from answering our own writes, so there is no loop. The handlers are removed when the tab is no longer in the visual tree (`Prune`, so closed tabs are released) or the window loses its color; the one-second timer remains as the safety net (it also creates the watch and applies the whole-tab fill, which the shell does not touch). The log says "Tab color put back after the shell changed it." once at the start and once at the end of a run. Not verified: a failed and a cancelled run (the same title change), saving, renaming, a connection change and the theme change (the same properties; the timer covers anything the handler misses).

**Auto-close per pair, and the block comment pair (#440, verified in SSMS 22.11, VSIX 0.200.34, light theme).** The single setting `autoClose` became four, `autoCloseQuote`, `autoCloseParenthesis`, `autoCloseBracket` and `autoCloseBlockComment` (`BehaviorSettings`, the group *Auto-close* of the page Editor helpers); `BehaviorSettings.AutoClosePairs` gives them as the flags `AutoClosePairs` that `AutoClose.Decide(text, caret, typed, enabled)` (Core) takes: a pair that is off does nothing (no closing, no step over, no Backspace removal), the others are unaffected. Migration: `autoClose` stays in the file format only as a read-only private member (`EmitDefaultValue = false`, so it is never written again); on read, on sets the quote, parenthesis and bracket on, off sets them off, the block comment keeps its default (on); a pair written in the same file wins (members are read in alphabetical order, the old name first); a file without any of them gives all on, as before. The values travel with the settings export/import (the JSON import uses the same deserializer; the SQL Prompt import never touched this setting). *Block comment:* typing `*` right after a plain `/` (not inside a string, a bracketed name or a comment, not after the end of a comment) inserts ` */` behind the caret, so `/*|` becomes `/*| */`; typing `*` where the comment's inserted closing ` */` or `*/` follows moves the caret over the space and the star (`AutoCloseAction.OvertypeCommentStar`), and the `/` that follows steps over the slash (`Overtype`), so typing `*/` ends the comment; Backspace right after `/*` removes `/*` and the untouched ` */` together (`AutoClose.TryGetPairDeletion`; a comment whose text changed keeps its closing). Limit: while a comment is being edited, a `*` typed in front of its ` */` also steps over it (the closing cannot be told from one that was inserted). The handler inserts the closing text asynchronously, so a script that types very fast (SendKeys) can type over the position before the closing is inserted; slow typing (as in the tests with `@@`) gives `/* */`, `/*abc */x` after typing `*/`, and Backspace after `/*` leaves nothing; unchanged for the other pairs. Verified: the four checkboxes in the settings window, the effect of the switch at once (block comment off gave `/*`, the parenthesis was still closed), the old settings file keys gone and the four new ones written. Not verified: the dark theme of the page (the same controls as the other pages).

### Code analysis: the rule catalog (#395, #396-#403)

**Catalog.** `AnalysisRules.All` (Core, `Analysis/Rules/AnalysisRule.cs`) declares every rule once: code, `CodeIssueKind`, category (best practice BP, deprecated DEP, execution EI, miscellaneous MI, performance PE, script SC, style ST), title, description, default on/off and severity. The codes of the reference catalog are used where the rule is the same (BP004 INSERT without columns, BP005 `SELECT *`, BP006 TOP without ORDER BY, BP007 type without length, BP010 `@@IDENTITY`, BP011 NULL, MI005 unused variable, ST001 old-style join); our own rules have the prefix `SP` (SP001 JOIN without ON, SP002 NOLOCK, SP003 unexpected end, SP004 function on a column, SP005 leading wildcard, SP006 NOT IN, SP007 implicit conversion, SP008 ambiguous column, SP009 unknown column of a temporary table). `CodeIssue.Code` gives the code of an issue. The settings window builds the *Code analysis* page from the catalog (`SettingsPage.RuleCatalog`): a filter box, *Enable all / Disable all* for the whole list and for each category, a check box with the code and title, the description with the severity and "off by default".
**Switches.** The rules that had a property in the `analysis` group before the catalog keep it (older files load unchanged; `AnalysisRule.LegacyGet/LegacySet`). Every other rule is kept in `analysis.rules` as a list of overrides `CODE:on` / `CODE:off` (only what differs from the default; older versions ignore the field). `AnalysisSettings.IsOn(rule | kind)`, `SetOn(rule, on)`. A rule that is off produces no squiggle, hint or repair.
**Implementation.** `CatalogRules.Run` (called at the end of `CodeAnalyzer.Analyze`) builds a `RuleContext` once: the tokens without comments, the parenthesis depth and the owner of every token, the statements (`StatementSplitter`), the modules (`CREATE`/`ALTER` of PROC, FUNCTION, TRIGGER, VIEW with name and body start) and the cursors of the batch; the rules are in `BestPracticeRules.cs`, `DeprecatedRules.cs`, `ExecutionRules.cs`, `MiscellaneousRules.cs`, `PerformanceRules.cs` and `ScriptAndStyleRules.cs`. They work on tokens, never on text in strings or comments, and stay silent on incomplete code. Defaults: on for clear mistakes and deprecated syntax, off for opinions (style, most performance hints). Repairs: BP001 (`NONCLUSTERED`), BP016 (`RETURN 0`), DEP001 (`WITH`), PE013 (`EXISTS` / `NOT EXISTS`), ST002 (`expr AS alias`), ST006 (`TOP (n)`), ST013 (`<>`), SC006 (CR LF for the rest of the script), and with the loaded metadata MI003 (alias in front of the column), PE001, PE002 and PE023 (the schema). The table sources of ST010 get no repair (qualified column references would break). The severity is fixed per rule (not configurable). `MI001` takes the table variables from `UnusedVariable` (the quick action *Remove Unused Variables* uses both). A script of 1500 batches (about 50 000 tokens) is analyzed with every rule on in well under a second (a test keeps it below 4 s).
**Verified** in SSMS 22.11 (VSIX 0.200.42, 2026-11-13): squiggles for `(NOLOCK)` without WITH, `DELETE` without WHERE, `COUNT(*)`, `sp_addlogin` and `= NULL` in a sample script; the settings page in the light and in the dark theme (headings, check boxes, filter `cursor` shows only the cursor rules, *Enable all* / *Disable all* buttons look like the rest of the window). Not looked at in SSMS: the individual messages of every rule (they are covered by the Core tests), the light bulb repairs of the new rules.
